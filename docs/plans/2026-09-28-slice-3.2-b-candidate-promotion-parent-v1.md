### 3.2 动作语义与安全/撤销线性化

- 要求调用者已经开始同一个 READ COMMITTED Session transaction，Engine.hide_parameters=True；canonical 非 nil tenant hint、43 ASCII unpadded base64url/32-byte canonical bearer；只临时算 hash作 bind；raw/hash 不进入 repr、log、exception/cause/context、audit或 prompt。
- 同一 SELECT 校验 token/user/org active、expires_at 非 NULL 且严格 > statement_timestamp()、tenant 全链一致、精确 p.permission_key；命中的 user/token/grant/permission 与 UTC checked_at 从 DB 推导。Principal.user_id、role name、caller verified flag、任意 witness constructor 均不参与授权。
- 单 SELECT 是该动作的授权线性化点，沿用 S31 READ COMMITTED snapshot 语义：撤销在该 SELECT snapshot 之前提交则拒绝；之后提交不会追溯撤回已开始动作，下一 SELECT 必须拒绝。checked_at 是检查语句时刻，不是事务 commit/可见时刻。不能声称未持锁的 SELECT 提供 commit 时仍有效保证。
- 不加 FOR SHARE/FOR UPDATE 或提权：现有 app 在 user_roles/role_permissions 没有 UPDATE ACL；隐式锁需权限/可能阻塞且会改变已接受授权模型。B1 在 Fins 观察前、final transaction进入/历史恢复前、candidate/series锁等待完成且写入前分别重新调用固定动作入口；动作witness取最后一次写入前SELECT，不缓存早期witness。
- 返回 witness 只在 repository 私有局部消费。公开 dataclass constructor 本身不提供安全 provenance，B API/DTO 不接受外部 witness。没有 Session.begin、commit/rollback、权限seed、issuer、token rotation/OAuth 或外部 endpoint。
- 授权 registered user 是此单位能证明的范围，不能断言真人在场/MFA；人工核验是调用动作承担的显式业务 attestation。typed service principal/issuer 当前缺失，另归 ServiceActor，不由 user subject/name 或 grant 文本推断。
- 无 grant、claim.review-only、NULL/expired/revoked token、disabled user/org、wrong tenant、invalid token 统一 EvidenceReviewUnauthorizedError；DB/隐藏参数/投影失败沿用 EvidenceReviewStorageError，usage/no transaction 沿用 EvidenceReviewUsageError。BaseException/cancellation 传播，caller transaction 回滚，零业务写。

### 5.2 NEW availability 与 causal eligibility 规则候选（必须独立审查）

旧 FactPitTimes/FactPitProjection 保持“原样时间 DTO，不授最终 PIT 使用许可”的语义，不改域 validators 或其可用性声明。B1 Fact.published_at / ingested_at / available_at 原样来自可信 source manifest 的 published_at / ingested_at / source_available_at；Fact.available_at 仅表示该 source revision 的平台资料可用原始时刻，绝不表示新 Fact 首次提交可见。reviewed effective/period 来自显式授权核验输入。

promotion receipt 独立增加 promotion_admitted_at=同PG final授权 SELECT checked_at；这是逻辑动作 admission model 的权威时刻，必须 >=source_available_at，不取max，不用宿主now/filetime/Agentdate补齐。跨钟出现倒置返回dependency unavailable、零write并以sameoperation重试。verified_at 同样取 final DB auth checked_at，但不能充commit visibility。statement_timestamp/transaction_timestamp/Fact.created_at 都不是commit实际可见时刻；当前source无精确commit witness，能力明确缺失。

为消除“commit后读回旧time就推断过去可见”的前视路径，B1使用独立 causal eligibility：在新的PG事务已经读到durably committed Fact+promotion receipt之后，才允许本次freshFins门；current-use输出read_at（新读取语句DB时刻）、promotion_admitted_at、exactrevision和本次owner witness。它证明本次已见提交结果，不证明任何过去decision_at曾可见。

新增窄 FactUseRequest 为 fact_id、purpose closed enum current/as_of、as_of UTC datetime或NULL。current必须as_of=NULL；as_of请求一律在读repo/Fins之前固定 historical_pit_consumer_not_supported 拒绝。public方法 validate_promoted_fact_for_use(scope,request)->PromotedFactCurrentUse 仅实现current分支，无silentcurrentfallback。下游不得直接凭available_at<=旧decision_at、旧RawTime DTO或promotion_admitted_at判断历史可用性；未来backtest/optimizer必须走Visibility单位接受的另一causal/commit gate，B1当前-use DTO不提供历史资格。

代价是历史PIT消费明确未交付，tracking=S32-B-Visibility（追加commit visibility witness及独立as-of定义/验证）。若独立review要求先完成该单位或改用其它authority模型，必须NEW计划，不让implementation作者把statementtime改名成firstvisible。这里是新consumer规则候选，Controller口头讨论不授规范权；完整Slice3.2/历史业务ready不能由B1current-use通过关闭。
