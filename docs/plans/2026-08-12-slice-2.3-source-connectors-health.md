### 2.2 Job 完成的精确定义

JobCompletion 表示“本次 source observation/result 已可靠持久化”，不是“provider 一定成功”。
下列 source outcomes 均以 JobCompletion 返回，并在 result 中保留真实结论：

- succeeded
- no_change
- partial
- failed
- skipped_disabled
- stale_subscription

只有尚未形成可持久化 source observation 且 source transaction 未提交的 closed execution
failure 才返回 JobFailure：

- SOURCE_INVALID：payload 无法安全识别，non-retryable，零 source row；
- SOURCE_OPERATION_BUSY：同 attempt 已有未收敛 owner，retryable，零 source row；
- SOURCE_INTERRUPTED：domain cancellation/drain，retryable，零 source row；
- REPOSITORY_FAILURE：PG/source repository 未提交，retryable，零 source row。

不得从 handler 返回 SafeJobErrorCode.CANCELLED。PG cancel intent、deadline、max attempts 的
唯一真源仍是 PostgresJobStore。terminal point-of-no-return之前的asyncio.CancelledError按§6.1.1完整
reap同步inner call后原样传播且不得持久化source observation；PONR之后durable repository decision优先，
outer task cancellation不得覆盖已经可能commit的结果，必须返回该closed completion/failure。两者不是
第二个CANCELLED error code。
dayu/investment/domain/jobs.py 的 SafeJobErrorCode 只新增 SOURCE_INVALID、
SOURCE_OPERATION_BUSY、SOURCE_INTERRUPTED；exact member/value为
``SOURCE_INVALID='source_invalid'``、``SOURCE_OPERATION_BUSY='source_operation_busy'``、
``SOURCE_INTERRUPTED='source_interrupted'``；REPOSITORY_FAILURE沿用既有
``REPOSITORY_FAILURE='repository_failure'``。``JobFailure``构造与persisted attempt receipt矩阵固定：
source_invalid ``retryable=False``，source_operation_busy/source_interrupted/repository_failure
``retryable=True``；反向组合构造即拒绝。unsupported
market/form、provider unavailable/rate-limit 等已形成真实 source observation时不使用 JobFailure。

### 2.3 Crash residual，不伪称跨事务原子性

source transaction 和 JobService.complete() 是两个事务。本 Slice不扩通用 Job prepared-decision
schema。若 source terminal 已提交，而进程在 Job complete 前崩溃：

- source run、health、alert 和 operation 不重复、不丢失；
- 若后续 attempt 存在，重放完全相同的 source result，零 Fins、零 health/outbox；
- 若 deadline、cancel、max attempts 使 JobStore 在无后续 attempt 时直接终结，Job envelope
  可与已持久化 source outcome 不同；source truth 保留且可审计。

这是接受的 residual。禁止声称 source terminal 与 Job terminal 强一致；若产品要求强一致，
必须 STOP 并另开通用 job_attempt_handler_decisions 设计，不得让 JobStore 读取 source 表。
另一个同类窄窗口是：handler 已提交 source terminal 并返回 ``JobCompletion`` 后，Worker 侧
cancellation signal 恰在 ``JobService.execute_claim`` 的返回后置检查前置位；既有 gateway 会把
该 completion 收窄为 ``HANDLER_REJECTED``。source truth 仍保留且不重做，Job envelope 可失败。
这是显式接受并必须测试的审计差异，不得回滚已提交 source truth 或伪造 ``CANCELLED``。

## 3. Pure contracts

### 3.1 Job handler、trusted scope 与 registries

修改 dayu/services/job_service.py：

~~~python
class JobExecutionHandlerProtocol(Protocol):
    @property
    def job_type(self) -> str: ...

    async def execute(
        self,
        scope: TenantScope,
        request: JobExecutionRequest,
        cancellation: JobCancellationSignalProtocol,
    ) -> JobCompletion | JobFailure: ...
~~~

这是对既有二参数``execute(request, cancellation)``的全量替换，不是overload或compat路径。
``JobExecutionHandlerProtocol``、``JobExecutionRegistry`` runtime structural check、所有production handler
（本Slice只有source handler）以及所有测试fake/stub必须在同一change迁移到精确三参数签名；owner test对
changed handler/fake做``inspect.signature``/Pyright gate并用AST/rg证明没有仍被registry调用的旧二参数
实现，避免runtime TypeError。

JobService.execute_claim 已持有 trusted TenantScope；它必须验证
scope.tenant_id == claim.tenant_id == request.tenant_id，并把原 scope 传给 handler。
禁止从 tenant_id 重建 Principal/TenantScope。JobExecutionRequest 仍精确八字段，绝不加入
lease、fence、raw token、worker id 或 repository handle。

在 handler result 类型检查后，若 result 是 ``JobFailure`` 且
``safe_error_code is SafeJobErrorCode.CANCELLED``，``JobService.execute_claim`` 必须返回既有
``_handler_rejected_failure()``；只有 ``PostgresJobStore`` 的 persisted cancel-intent 分支能生成
generic CANCELLED receipt。该门禁适用于所有 handler，不能只靠 Source handler 自律。

JobHandlerRegistryProtocol / JobHandlerRegistry 新增：

- seal() -> None
- is_sealed: bool
- descriptor_count: int

JobExecutionRegistry 新增：

- seal() -> None
- is_sealed: bool
- handler_count: int

规则：seal 前 append-only；同 descriptor + 同 handler identity 重复注册幂等；drift/replacement
拒绝；seal 后任何 register 均拒绝，包括 exact replay。composition-owned immutable
``EXPECTED_PRODUCTION_HANDLER_BATCH``是batch/count唯一真源；Slice 2.3该tuple精确只含source
descriptor+handler pair。production先注册整个batch，再seal两个registry并断言counts==len(batch)==1
及source lookup identity，最后发布services。未来Slice新handler必须在同一change扩batch及expected
count/tests；global count=1不是永恒public invariant，不能runtime unseal。

``SourceFinsTerminalCandidate``构造期exact矩阵（repository只做freshness/drift override，不修补非法
candidate）：succeeded要求documents非空、error NULL、failed=0；no_change要求documents=()、error
NULL、downloaded=reused=failed=0（ignored/discovered可非零）；partial要求documents非空、
error=partial_batch、downloaded+reused>0、failed>0；failed要求error IS NOT NULL且只为
unsupported_market/unsupported_form/provider_rate_limited/provider_unavailable/fins_invariant；
stale_data仅repository freshness override，connector candidate不得提出；
unsupported/rate-limit/fins_invariant全counts零，provider_unavailable按§4.1允许全零或status=ok clean
correlated failed/ignored counts且documents=()；所有分支documents长度=downloaded+reused、discovered
求和、latest date iff documents非空。candidate不得提出skipped_disabled/stale_subscription或任意
outcome/error/count/docs不匹配；构造即fail closed，repository绝不“猜”合法组合。
``SourceNoProviderTerminalCandidate``还必须与operation acquire disposition精确对应：disabled只能配
disabled，binding_drift只能配stale；ready配no-provider或disabled/stale配Fins candidate均是protocol
misuse、零mutation fail closed。该判断不依赖当前health反推历史：repository以operation当前generation
持久化的``owner_binding_disposition``为authoritative acquire fact；operator在acquire后reenable health也
不能擦掉此前disabled事实。terminal revalidation仍独立检查current subscription/source/security：任何
business binding drift覆盖为stale；只有health head的后续变化不重写owner disposition，按§7 sticky/
late-observation规则处理provider或no-provider candidate。

### 3.4 Job payload 与 result

descriptor 固定：

- job_type = investment.source-sync.v1
- payload_schema_name = investment.source-sync
- payload_schema_version = 1
- max_attempts = 3
- retry_base_seconds = 30
- retry_max_seconds = 300
- lease_duration_seconds = 900

payload 是 schema_version=1 的 closed discriminated union：

1. manual：subscription_id、expected_subscription_version、trigger_id、frozen source definition /
   subscription config / security / canonical ticker / MIC / connector、request_fingerprint；
2. scheduled：subscription_id、source_definition_id、expected_subscription_version、stable schedule_key、
   source_request_fingerprint；不伪造 occurrence UUID，第一 attempt 在 source operation 内冻结当前
   binding/config/security/query window。这里的五个业务字段与§3.2.1
   ``ScheduledSourceSyncPayload``逐字段相同，不得在summary省略version/fingerprint。

manual Job idempotency key 精确为：
source-sync-trigger:v1:{subscription_id}:{trigger_id}

作为0006 prerequisite，既有``PostgresJobStore.enqueue``是new-enqueue payload canonical admission唯一owner。
它必须在调用session factory、计算request fingerprint、执行任何SQL或返回给可能publish的JobService之前，先对
``request.payload.canonical_bytes``执行strict UTF-8 decode，再调用domain-equivalent canonical parser（schema name/version
精确取request payload），重编码并要求returned canonical bytes与SHA分别等于request payload bytes与SHA。invalid UTF-8、
sensitive/unsupported/float、duplicate key、BOM、trailing bytes、noncanonical JSON、SHA自洽但noncanonical bytes，或
bytes/SHA drift均抛closed ``JobInputError``；session factory/SQL/persisted row/wakeup publish调用均为零。JobService不得
复制该validation，也不得先publish；经JobService调用时只允许一次Store方法入口，由Store preflight在任何session/DML前拒绝。

0006 prerequisite只完成上述enqueue admission、三列持久化、retry只改current``available_at``及Source provenance改读
original列；它**不**新增``JobIdempotencyRecord``、``JobStoreProtocol.get_by_idempotency_key``、JobService lookup或
Source facade recovery。下述record/protocol/service/lookup/reconstruction完整surface仍唯一属于随后Item 6 main exact20-path
implementation及其既有exact lookup tests，prerequisite测试不得import、mock、调用或要求future surface。

为在首次commit成功但response丢失、随后source binding已经漂移时仍能证明原请求并恢复，
``dayu/investment/domain/jobs.py``新增pure frozen ``JobIdempotencyRecord``，精确字段为
``tenant_id: TenantId``、``definition_id: UUID``、``job_id: UUID``、
``descriptor: JobHandlerDescriptor``、
``idempotency_key: str``、``payload: CanonicalJobDocument``、``payload_sha256: str``、
``request_fingerprint: str``、``original_available_at: datetime``、``deadline_at: datetime``。构造期typed parse/
canonical re-encode只验证generic ``CanonicalJobDocument``与outer payload SHA、aware time/identity，并以
完整七字段descriptor、payload自身的``schema_name/schema_version``以及immutable
``original_available_at``重建generic``JobEnqueueRequest``后重算request fingerprint；source payload schema的
strict parse与caller-intent compare仍只由``InvestmentSourcesService``拥有，jobs domain不得import/猜Source
schema。Store还要求definition_id、locked definition descriptor与record descriptor逐字段相同；Source facade
再要求fixed source descriptor。record不暴露当前Job state、attempt、lease或definition
active状态。``JobService.get_by_idempotency_key``只read-only委托Store一次并原样返回
``JobIdempotencyRecord | None``；它不strict parse Source payload、不比较caller intent、不构造
``JobEnqueueReceipt``、不publish且不产生任何mutation。只有``InvestmentSourcesService``在命中后完成
Source-owned strict payload parse、caller-intent compare与record identity验证，才重建原enqueue语义的
``JobEnqueueReceipt(tenant_id=record.tenant_id, definition_id=record.definition_id,
job_id=record.job_id, state=JobState.READY, idempotency_reused=True)``；即使durable job
当前处于任意state（包括LEASED/SUCCEEDED/FAILED/CANCELLED）或definition后来disabled，也不得用current
projection拒绝recovery。descriptor是job_type的唯一真源，不重复另存``job_type``字段。

``JobStoreProtocol``与``JobService``各新增同一个read-only tenant-scoped facade：

~~~python
def get_by_idempotency_key(
    self,
    scope: TenantScope,
    *,
    descriptor: JobHandlerDescriptor,
    idempotency_key: str,
) -> JobIdempotencyRecord | None: ...
~~~

lookup必须先用tenant + exact descriptor解析唯一definition，再只用``(tenant_id, resolved definition_id,
idempotency_key)``查询definition-scoped既有unique identity，cross-tenant或exact definition/key缺失均
等价于missing；不能只按key查、不能tenant-wide扫描同key、不能publish/mutate。其它合法definition下同key的
row不影响结果。该接口没有original definition identity或job_id，故cross-definition relocation在此surface不可观察，
按exact definition/key missing处理；禁止为检测它改成tenant-global key unique或把合法B/K误报tamper。命中时同caller intent可恢复原Job；同key但caller
intent漂移由Source facade抛``JobIdempotencyConflictError``；Store命中row却发现definition/descriptor、
canonical payload/hash、persisted request payload schema identity、generic request fingerprint或immutable time identity漂移时精确抛既有
``JobRepositoryFailureError``，JobService原样传播，Source facade再按§9统一精确映射为
``SourceServiceUnavailableError(unavailable)``。``JobRepositoryFailureError``没有typed code，绝不能读
current binding补值、按异常message或persisted shape分支、伪造``persisted_invariant``诊断，或把tamper当miss。

scheduled Job idempotency 继续由 ScheduleService 唯一公式拥有：schedule_id、schedule_version、
scheduled_for。不同 occurrence 必须得到不同 Job。

result canonical document 精确包含：schema_version、outcome、source_sync_run_id、
producer_attempt_id、source_receipt_sha256、retry_recommended；不得加入调用时变化的 replay marker。
retry_recommended 只表示下一 occurrence/新 manual trigger 的运营建议，不驱动同一 Job retry。

### 3.5 时间、窗口与大小上限

Fins 的真实 source 时间目前只有 calendar date。禁止伪造 UTC source timestamp：

- FinsWorkerSourceDocument.source_observed_date: date；
- FinsWorkerSyncResult.latest_source_observed_date: date | None；
- freshness 按 PG UTC today 与 date 的 calendar-day 差比较；
- observed_at、started_at、finished_at 只描述本次 PG 执行时刻。

query/as-of window从业务可用时刻冻结，绝不从执行cutoff deadline推导：

- end_date = job_runs.original_available_at.astimezone(UTC).date()
- start_date = end_date - timedelta(days=lookback_days - 1)
- 两端 inclusive；N=1 同日；月末、闰日只用 calendar arithmetic。

manual builder使用``SourceSyncEnqueueRequest.available_at``生成snapshot，enqueue后repository校验其
等于locked ``job_runs.original_available_at``；scheduled首次acquire使用locked
``job_runs.original_available_at``（即occurrence首次enqueue fire/available seed）生成并持久化snapshot。
mutable ``job_runs.available_at``只负责当前retry eligibility，任何lookup、provenance、window或takeover都不得把它
冒充原请求事实。deadline_at只用于§6.1 live cutoff；即使跨UTC
午夜也不得移动source window。replay/takeover
读取原 bytes/hash，绝不用新时钟重算。

硬界限：documents <= 500；DownloadEvent <= 16064；canonical source receipt/result <=
8,388,608 bytes；forms <= 16。``FinsWorkerSyncRequest``不含ticker aliases；只有§4.1 runtime对pipeline的
调用使用``ticker_aliases=[worker_request.ticker]``，不接受外部alias输入。one-over 必须 closed invariant，关闭流，
不得静默截断。partial只在status=ok、已有verified documents且同时存在filing failure时成立；其它
shape严格按§4.1/§4.3映射，不以“有过buffer”自行降级为partial。

### 4.3 DownloadEvent 与 locator 唯一化

DefaultFinsWorkerSourceSyncRuntime 必须消费本次 owned DownloadEvent stream，不得同步前后扫描 repository，也不得
把 list_filings() 当 locator 真源。每个event.ticker必须等于request canonical ticker。
DownloadEvent及其raw dict/``Any`` wire解析严格封装在新component private helpers内；public
``FinsWorkerSyncResult``只含§4.1 strict DTO，绝不泄漏DownloadEvent或mapping。2.3不需要修改
``dayu/fins/pipelines/download_events.py``；若实现证明必须改变upstream wire class/producer shape，因其
不在allowlist立即STOP回Controller，不能悄悄扩scope。

private ingress只对本边界拥有且后续用于identity/canonical correlation的子树做strict
narrowing：``FILING_STARTED``的上述identity scalar字段、``FILING_COMPLETED/FILING_FAILED``的
``filing_result``与所有存在的flat mirror、``PIPELINE_COMPLETED.payload["result"]``。每个owned
object递归复制成fresh closed ``JsonValue``，拒绝非字符串key、dataclass、``Path``、bytes、
NaN/±Infinity等非有限float与其它非JSON值；未通过narrowing的raw ``Any``绝不传给
canonical encoder。``FILE_DOWNLOADED/FILE_SKIPPED/FILE_FAILED``的payload可合法携带SEC
``FileObjectMeta``等legacy object：这三类只校验event order、ticker、document_id关联与cap，完全
忽略payload，禁止递归JSON校验。``COMPANY_RESOLVED``（以及不参与上述关联的pipeline
progress event）不对整个payload做JSON/canonical校验；只校验全局event order/ticker/cap。
private helper允许在既有``DownloadEvent.payload``读取点立即消费legacy ``dict[str, Any]``，但新增helper
自身及其返回值的signature不得显式声明``Any``/``object``，不得用cast/getattr/hasattr逃逸；实现若无法在
现有边界内完成typed narrowing而必须扩大该escape或修改``download_events.py``，立即STOP回Controller。

SEC/CN/HK filing terminal 的唯一 wire 真源是 ``event.payload["filing_result"]``。该值必须是
object；顶层扁平字段只是兼容镜像，任一同名字段必须与nested canonical value精确相等，否则
invariant_failed，禁止回退读取顶层。普通terminal要求
``event.document_id == filing_result.document_id != ""``；FILING_COMPLETED只允许nested status
downloaded/skipped，FILING_FAILED只允许failed。source_observed_date只取nested filing_date的ISO
calendar date，不取report_date/emitted_at。

FILING_STARTED identity：SEC使用event.document_id和payload form_type/filing_date/report_date/
accession_number；CN/HK使用event.document_id和payload form_type/filing_date/fiscal_year/
fiscal_period/source_id。每个普通terminal必须匹配一个且仅一个started，反之亦然。

CN/HK candidate_not_found是唯一无started的synthetic terminal：event type=FILING_COMPLETED、
event.document_id is None、nested document_id=""、status=skipped、form_type属于request、
filing_date/report_date均NULL、reason_code==skip_reason==candidate_not_found；每个request form最多
一个，只计ignored/discovered，不进入locator/identity map。SEC不得生成该special case。

PIPELINE_COMPLETED必须恰好一次、必须是最后一个event且stream随后clean exhaustion；payload key
精确为result，status路径精确为 ``payload["result"]["status"]`` 且只为ok/cancelled/failed。
所有status先验证result.ticker=request ticker、result.action=download、US的result.pipeline=sec且
CN/HK的result.pipeline=cn。status=ok/cancelled要求``result["filters"]`` exact keys为forms/start_dates/
end_date/overwrite：overwrite=false、end_date=request end ISO、每个start_dates值=request start ISO，
forms归一集合等于request forms（US输出lexical sorted；CN/HK输出FY/H1/Q1/Q2/Q3/Q4 semantic order，
不因顺序差异误判）。status=failed允许filters={}或上述exact object，拒绝partial/mismatched filters，
因为现有early provider failure公开default empty filters。status=ok时，
result.filings必须按event顺序与全部terminal nested object canonical-byte等价，且
summary.total/downloaded/skipped/failed分别精确等于filings长度与raw status计数；ok可含failed
filing，不能单独当成功。status=failed是现有CN/HK/SEC pipeline-level public provider failure：在
此前事件逐个wire/identity检查仍成立的前提下，不要求其``result.filings``或default-zero summary与
已发terminal相等，丢弃所有buffered documents/counts并映射unavailable；status=cancelled同样丢弃。
任何已证实flat/nested mirror、duplicate/conflicting/after-terminal漂移仍优先invariant，不能被随后
failed/cancelled terminal洗掉。

FILING_COMPLETED 的分类：

- downloaded：必须读取 exact (ticker, document_id, FILING) source meta；
- skipped + meta 存在：仅在 ingest_complete、not deleted、form/date/window identity 全等时
  分类 reused；
- skipped + meta 不存在：只允许 rejection_registry、6k_filtered、candidate_not_found，
  分类 ignored；candidate_not_found 可有空 document_id，其余 terminal 必须非空；
- 未知 skip reason、meta 漂移或半持久化均 invariant_failed。

允许 reused 的 reason 只限：already_downloaded_complete、source_fingerprint_matched、
remote_files_equivalent、not_modified、remote_fingerprint_matched、pdf_sha256_matched；reason本身
不构成证据，仍须通过完整 meta/locator/readback。不在两组 closed集合中的 skip一律 invariant。

outcome优先级固定：

1. ``asyncio.CancelledError`` 原样re-raise；
2. stream外部的domain CancelledError或adapter-local cancel_checker命中 -> typed cancelled并丢弃buffer；
3. 已证实event cap/duplicate/conflicting/after-terminal等protocol invariant -> invariant_failed；
4. stream异常终止且尚无已证实invariant：公开typed rate-limit exception才rate_limited，其余
   timeout/transport/provider/runtime exception -> unavailable，已缓存documents不构成partial；
5. clean exhaustion才校验唯一pipeline terminal；缺失/未知status为invariant；valid failed ->
   unavailable全空/零，只有此前无任何proven invariant的clean valid cancelled才typed cancelled；
6. 只有status=ok执行result.filings/summary exact correlation：verified documents>0且filing
   failed_count>0 -> partial；无filing failure -> complete；无verified documents且failed_count>0 ->
   unavailable并保留clean-correlated discovered/ignored/failed counts；其它 -> complete/no_change。

downloaded/reused 的 locator 只能由 DefaultFinsWorkerSourceSyncRuntime 构造：读取 document_version、
source_fingerprint；打开 primary source 实算 bytes SHA；构造 ArtifactKind.SOURCE +
LocatorKind.DOCUMENT + DocumentLocatorPayload 与 EvidenceLocatorRequest；调用现有
resolve_evidence_locator(request)，再调用 validate_evidence_locator(projection) readback。
任何 document meta/locator/readback 失败使该 document 失败；不得把路径、URI、bucket、key、
FilingSummary 或内部 storage object 写入 public projection。

合法 no-change 精确为complete且documents=()：pipeline total=0，或全部terminal skip都被closed规则
分类为ignored。skipped + verified complete meta分类reused并产生document，因此“all raw skipped”若含
reused仍是succeeded，绝不能一概叫no_change。零locator本身不自动失败；只有返回document却缺合法
source_observed_date才invariant/stale；
不得用 download/PG time 补 source date。

Fins result 到 source outcome 的唯一映射：

- complete 且 documents非空 -> succeeded；complete 且documents空 -> no_change；
- partial 只有 documents非空且failed_count>0时合法 -> partial；
- rate_limited、unavailable、unsupported_market、unsupported_form、invariant_failed -> failed；Fins
  stale不可达，repository freshness override才生成stale_data failed；
- cancelled -> 不写 source terminal，返回 SOURCE_INTERRUPTED；
- retry_recommended 仅 partial、rate_limited、unavailable 为 true，其余 false。

freshness 的 stale override 使用 terminal transaction由single raw clock导出的§6.3 monotonic
authoritative terminal UTC date与
latest_source_observed_date 比较；Service/Storage共用 Source domain pure helper，禁止提前用
本机时间判断。documents为空的合法 no_change 不执行 stale override。

### 4.4 Cancellation 与嵌套 stream owner

- asyncio.CancelledError：原样 re-raise；
- dayu.contracts.cancellation.CancelledError 或 cancel_checker 命中：typed cancelled；
- Investment execution service将typed cancelled映射SOURCE_INTERRUPTED retryable，handler只委托，零source observation；
- success、clean exhaustion、typed cancel、domain/mapping error、protocol invariant与
  ``asyncio.CancelledError``每条路径都必须让每个direct owner执行
  ``finally: await inner.aclose()`` exactly once。

当前外层native async generator被``aclose``不会自动关闭它正悬停的inner generator；而历史合同把这些
返回值标成``AsyncIterator``，静态类型又没有``aclose``。本corrective change对download-only链做一次精确
替换：所有直接拥有/返回该download stream的协议、wrapper、workflow和leaf统一返回
``AsyncGenerator[T, None]``；不扩大到process/upload stream，不改legacy CLI/job-manager exhaustive consumer，
也不新增custom stream wrapper/protocol。
``outer early aclose``只适用于这些返回``AsyncGenerator``的wrapper/workflow层；
``DefaultFinsWorkerSourceSyncRuntime.sync_worker_source``与``persist_rejected_filing_artifact``都是普通
``async def`` coroutine而不是async generator，它们没有``aclose``入口，必须以caller task正常完成/异常或
``asyncio`` cancellation进入自身``finally``并关闭direct inner，测试不得对coroutine伪造outer ``aclose``。

exact传播与direct owner如下（箭头左侧只close自己直接取得的右侧inner，不跨层close）：

1. ``pipelines/base.py::PipelineProtocol.download_stream``与
   ``source_sync_runtime.py::FinsSourceSyncDownloadPipelineProtocol.download_stream``返回
   ``AsyncGenerator[DownloadEvent, None]``；``DefaultFinsWorkerSourceSyncRuntime.sync_worker_source``是本
   Slice coroutine root owner，按§4.1 exact coroutine signature绑定pipeline stream后，在success、error、

## 6. Source operation 与 handler 状态机

### 6.1 Operation 不是 Job 状态镜像

source_sync_operations 只有 ACTIVE / TERMINAL：

- ACTIVE：尚无terminal source observation；owner generation只有在join到live current Job lease时
  才表示可执行，expired/terminal Job上的ACTIVE只是中断审计，不伪造source terminal；
- TERMINAL：source result 已提交，以后只重放。

不保存 authoritative lease_expires_at，不存在 RETRY_WAIT。acquire 与 terminal transaction 都必须
逐行执行相同且唯一的 ``SELECT ... FOR UPDATE NOWAIT`` 序列；每一张可能阻塞的Source序列row都带
``NOWAIT``，不允许plain ``FOR UPDATE``、换序、合并成无序 join、session/local``lock_timeout``或另加表级
``LOCK TABLE``：job_run -> job_definition -> job_attempt -> job_lease -> source_operation -> subscription ->
source_definition -> security -> health_state。job_runs没有current_attempt_id；精确 live predicate 为：

1. 按tenant+job锁job_run；立即按该row.definition_id锁job_definition并验证request definition/descriptor、
   fixed source descriptor；acquire还要求request definition/descriptor逐字段等于locked
   ``job_runs.definition_id``与definition immutable descriptor，terminal没有这些caller字段，只从locked
   job_run追到definition并验证相同identity与fixed immutable descriptor。**对已经处于LEASED的Job，当前
   ``job_definitions.status``既不是acquire也不是terminal的live predicate**：active admission只属于
   generic Job owner在形成lease之前的claim/admission，Source repository不得在lease形成后重新执行第二份
   definition-status admission。两条Source路径仍必须按本锁序对definition执行``FOR UPDATE NOWAIT``，以串行化
   identity/descriptor与并发status update；status update占锁产生的original typed ``55P03``在rollback成功时返回
   ``unavailable``（rollback失败仍按§9最高优先为``transaction_aborted``），而disable
   已提交后的重试在其它live条件成立时仍可acquire/terminal成功。definition在Job已lease后被disabled不使当前
   live Job失效，也不覆盖source outcome。再由job current attempt number
   锁job_attempt，再由attempt fence锁job_lease；
   同job operation存在则锁该行，不存在时job_run row lock串行化same-job insert，禁止先查/锁operation
   再反向锁job；
2. 依operation绑定或candidate锁subscription、subscription指向的source_definition与security-target
   security，最后锁可选health head；missing health由subscription row lock串行化insert；
3. 只有拿到全部可能阻塞的row locks之后才调用一次fresh raw ``clock_timestamp()``；随后以该raw值验证job
   state=leased、cancel_requested_at IS NULL、deadline_at>clock、
   current_attempt_number=request.attempt_number；attempt id=request.attempt_id、state=leased、
   attempt.lease_expires_at>clock；lease.tenant_id=trusted scope/job/attempt tenant、
   lease.job_run_id=locked job_run.id、lease.attempt_id=locked attempt.id、released_at IS NULL、
   fence/token identity与attempt当前lease字段逐值相等。0003的独立FK不能证明cross-job pairing，因此
   任一persisted lease lineage拼接漂移必须抛``SourceSyncRepositoryFailure(persisted_invariant)``、整事务
   rollback且零source DML。锁前取得的旧clock不得用于live判定；
   ``job_leases.expires_at``仅是claim时初始handle的
   历史审计值，heartbeat不更新它，任何live/acquire/terminal判定都不得读取或比较它；
4. 只有上述全部NOWAIT锁已成功取得后，才允许任何source INSERT/UPDATE；此前不得写operation/head或其它
   source row。然后验证request/persisted payload/binding/current identity并做takeover或terminal DML。source
   definition/security在0001允许
   app UPDATE，因此两行锁是acquire/terminal之间drift判断的serialization edge；不得只重读不加锁，
也不得把它们另设为未经迁移证明的immutable truth。所有本Slice source acquire/terminal路径严格使用
上述含job_definition的同序；真实双connection NOWAIT test覆盖definition status UPDATE占锁与Source
typed conflict/rollback，不允许任何Source路径先锁attempt再回锁definition。

任一NOWAIT conflict只接受PostgreSQL SQLSTATE ``55P03`` / exact psycopg
``psycopg.errors.LockNotAvailable``这个typed事实；它作为original operation failure时仅在rollback成功或无需rollback时映射
``SourceSyncRepositoryFailure(unavailable)``，rollback自身失败（包括rollback自身同一typed lock failure）必须按§9映射
``SourceSyncRepositoryFailure(transaction_aborted)``。禁止按driver message、lock owner/table name或timeout猜分支。
其它SQLSTATE继续按§9既有infra/persisted-invariant矩阵处理。acquire conflict整transaction rollback，零
operation/Fins；terminal在PONR后conflict也整transaction rollback，零run/health/snapshot/outbox且operation
保持ACTIVE，inner typed failure是authoritative outcome，execution service返回retryable
``REPOSITORY_FAILURE``。未来live attempt可按generation takeover并exact-once terminal。NOWAIT只适用于本
Slice Source repository序列，不改变generic Job/Schedule repository的accepted lock protocol。

existing named test
``test_concurrent_source_definition_or_security_update_serializes_with_acquire_and_terminal_revalidation``必须在同一
测试名内扩展definition status并发矩阵：connection B持有definition status UPDATE锁时，acquire与terminal均
bounded返回``unavailable``且零Source DML；B提交``disabled``后，两条路径重试都不得仅因current status拒绝，
而应在其余job/attempt/lease/binding条件成立时成功。该扩展不新增测试名、schema、protocol method或writable path。

raw token/fence值永不进入handler request；repository只使用已持久化identity。heartbeat只延长
``job_attempts.lease_expires_at``，source live truth与既有JobStore完全一致。没有health row时，
最后一把health锁在security之后以同一顺序执行head insert/CAS；并发terminal不得先锁health再
回锁operation。所有分支，包括terminal replay、no-provider与late lease rejection，均遵守此序列。

Acquire decision：

- 无 operation：冻结 execution snapshot bytes/hash，插入 ACTIVE generation=1；
- 同 job 已 TERMINAL：terminal_replay，返回 persisted canonical result；
- ACTIVE owner 是当前同 attempt：busy，零 Fins/zero mutation；
- ACTIVE owner 是旧 attempt：只有新 attempt 是 job current live lease 时 generation+1 takeover；
- 其它 identity mismatch/invariant：fail closed。

如果所有attempt都在source commit前因repository/cancellation失败，且Job随后因deadline、cancel或
max attempts终结，operation可物理保留ACTIVE；它不允许再acquire、不更新health/outbox，也不生成
虚假source_sync_run。本Slice没有operation query/list public consumer，不新增retry_pending/abandoned/
invariant_failure public enum、DTO、protocol method或持久化列；``SourceOperationEffectiveState``只含
acquire decision实际可返回的live/terminal。终结Job上的残留ACTIVE仅能由audit SQL结合Job rows解释，
后续retention/cleanup可另做但不能删除该审计行，JobStore也不回调source repository。

stale A 在 B takeover 后 terminal commit 必须因 owner_attempt/generation/live lease 不匹配而
失败，零 run/health/outbox。

每次首次acquire/takeover都在上述锁内把当代current事实写为operation
``owner_binding_disposition=ready|disabled|stale``；takeover允许它与owner/generation/acquired_at一起改变，
TERMINAL后保持不变。decision acquired返回该持久化值；busy/terminal replay不暴露一个可误当新acquire的
disposition。record_terminal只接受与stored owner generation/disposition匹配的candidate；例如disabled
acquire后operator reenable再terminal，disabled no-provider仍合法且零Fins，不能因current head healthy而被
误判forgery。反之caller伪造disabled/stale reason必被数据库owner fact拒绝。

### 6.1.1 Async execution 对同步 repository 的唯一 offload / cancellation contract

``SourceSyncRepositoryProtocol``七方法保持同步，``SourceSyncExecutionService``是execution路径把同步PG
调用移出event loop的唯一owner；handler、connector、repository和Worker都不再包第二层executor。本模块
private helper精确分成两类（不进入public protocol/export，callback ban仍适用于DTO/repository/public
connector而非这里的typed private adapter）：

~~~python
async def _await_acquire_operation(
    repository: SourceSyncRepositoryProtocol,
    scope: TenantScope,
    request: SourceOperationAcquireRequest,
) -> SourceOperationAcquireDecision: ...

async def _await_record_terminal_after_point_of_no_return(
    repository: SourceSyncRepositoryProtocol,
    scope: TenantScope,
    request: SourceTerminalRecordRequest,
) -> SourceTerminalRecordDecision: ...
~~~

两者都精确创建一个``asyncio.create_task(asyncio.to_thread(...))``作为inner call唯一owner，并在循环中
``await asyncio.shield(inner_task)``直到真实done；禁止直接在event-loop调用同步repository、fire-and-forget
thread、取消inner task或只等第一份outer cancellation。acquire内已包含locked current-binding read，execution
service禁止另做未offload的current read；若未来在本Slice实现需要同一execution路径调用
``get_executable_binding``，必须使用与``_await_acquire_operation``完全相同的pre-PONR owned/reap helper，
不得另造semantics。

pre-PONR/acquire规则：首次或重复``asyncio.CancelledError``只记录第一份，继续shield/reap至inner真实结束；
若有outer cancellation，inner结束后才原样re-raise第一份（inner exception只被读取以免orphan warning，不覆盖
outer cancel）。因此acquire可能已留下可takeover的ACTIVE audit，但取消后绝不进入Fins/terminal；若无outer
cancel则返回inner decision/exception。domain cancellation signal在后续边界检查为
``SOURCE_INTERRUPTED``。to-thread/shield/reap仍用于database/network latency与thread ownership，绝不据此声称
heartbeat能在Source已锁job_run后越过后续row contention更新同一Job：§6.1 NOWAIT使中途conflict立即typed
rollback/release earlier locks，随后generic heartbeat才可按其既有协议推进。

terminal PONR规则精确为：execution service已构造closed candidate后，在event-loop线程同步执行最后一次
``cancellation.is_cancel_requested()``；若为true，立即返回``SOURCE_INTERRUPTED``且不调用
``record_terminal``、零source mutation。该check与随后
``asyncio.create_task(asyncio.to_thread(repository.record_terminal, scope, request))``之间不得有``await``、
callback或其它control transfer；inner task成功创建的瞬间才是point-of-no-return，创建失败则尚未越界且零
repository call。PONR后不得再读domain cancellation signal或把outer cancellation映射为Interrupted：helper
吞下等待期间任意次数outer``asyncio.CancelledError``，反复shield并reap inner真实结果。inner outcome成为唯一
authoritative action：含persisted result/receipt的recorded/stale_subscription decision必须由execution service
无额外``await``地立即构造并返回byte-identical``JobCompletion``，handler同一call stack原样返回；
lease_lost/job_not_live仍按其零mutation decision返回``SOURCE_INTERRUPTED``，repository exception仍映射
``REPOSITORY_FAILURE``。outer task cancellation不能覆盖任何一种inner outcome，尤其禁止source commit后再由
Source execution报告cancellation。既有JobService在handler返回后的domain-signal gate仍可能按§2.3收窄为
HANDLER_REJECTED，但不会把已提交source truth改写为CANCELLED/Interrupted。

fake测试用可控blocking repository同时覆盖pre-PONR单次/重复outer cancel与PONR单次/重复cancel：前者reap后
传播首份cancel且零Fins，后者recorded时必须返回durable completion且thread无orphan，这个PONR coverage保持。
真实PG NOWAIT test用connection B先持有§6.1中间row；connection A source acquire/terminal在bounded test
deadline内精确返回``unavailable``而不是等待，整事务rollback并释放先取得的job_run等locks。只有证明A已
返回/释放后，才由真实generic heartbeat transaction推进``job_attempts.lease_expires_at``；Source rollback
完成前heartbeat不得越过A持有的job_run。acquire路径断言零operation/Fins；terminal PONR路径断言零
run/health/snapshot/outbox、operation仍ACTIVE且execution返回retryable REPOSITORY_FAILURE。随后驱动下一live
attempt按generation takeover并exact-once commit，证明无orphan thread/重复observation。禁止sleep，以
barrier/events、bounded timeout和真实row证据断言；不修改generic Job lock协议。

### 6.2 Execution service 顺序

下列十步全部由``SourceSyncExecutionService.execute_source_sync``拥有；handler只做§3.3 exact one-call
delegation，不复制parse/error/state逻辑：

1. strict parse Job payload；不识别时 SOURCE_INVALID；
2. manual把payload内frozen snapshot原样作为candidate，绝不按当前binding重写；scheduled只strict
   parse payload并传``candidate_execution_snapshot=None``，不在handler用deadline/local clock构造window；
3. 通过§6.1.1``_await_acquire_operation`` await acquire operation，绝不在event loop直接调用同步repository。
   repository按§6.1锁序读取job payload与current binding；scheduled missing/
   non-executable在插operation前抛typed SOURCE_INVALID。首次scheduled acquire在这些锁内从current
   binding+locked ``job_runs.original_available_at``生成并冻结authoritative snapshot，避免步骤2与锁
   之间的过期bytes；首次manual冻结payload snapshot。locked job definition只重验identity与immutable
   descriptor；already-LEASED Job的current active/disabled status不参与本步骤live判断。ACTIVE takeover与首次acquire随后都把persisted
   snapshot逐字段对照当前subscription/source definition/security company/config/ticker/MIC/active identity：任一
   origin drift均返回binding_disposition=stale，snapshot保持immutable；identity精确但subscription或
   health disabled返回disabled；其余ready。禁止takeover用current binding覆盖persisted snapshot；
4. terminal_replay直接返回persisted byte-identical JobCompletion，busy返回
   SOURCE_OPERATION_BUSY；acquired必须使用decision内repository已持久化的snapshot、SHA与
   binding_disposition，不能继续使用调用者candidate；
5. 任一origin stale：零Fins，以``SourceNoProviderTerminalCandidate(binding_drift)``记录
   stale_subscription terminal；scheduled/manual disabled：零Fins，以
   ``SourceNoProviderTerminalCandidate(disabled)``记录skipped_disabled terminal；两者都不更新
   health，不把binding drift伪装为provider failure；
6. ready才调用Fins；Fins调用期间不持PG transaction；
7. 用typed ``SourceFinsTerminalCandidate``或上述no-provider candidate进入§6.1.1 final cancellation check；
   未取消才跨PONR并由``_await_record_terminal_after_point_of_no_return``调用record_terminal；terminal
   transaction严格按§6.1逐行锁序重新验证live attempt、owner generation与冻结snapshot SHA，并在
   锁内重读subscription/version/status/security identity；
8. terminal revalidation发现Fins期间任一binding/version/status漂移时，repository丢弃caller
   candidate并authoritative override为stale_subscription；发现job cancel/deadline/lease loss则零
   source row返回job_not_live/lease_lost；
9. repository复用§6.1全部row lock后取得的那一次raw PG clock（不得再次读clock），按§6.3先导出
   monotonic authoritative terminal time，再自行生成run/snapshot/
   alert UUID、最终outcome/error/count/date/
   latency、canonical receipt/result/hash与health/alert transition，原子写一条source run、可选health
   snapshot/head、可选semantic alert、operation terminal；
10. execution service只返回decision中刚持久化的canonical JobCompletion result；handler原样转交；
    Worker后续complete/fail仍
    完全由JobService/PostgresJobStore拥有。

若 subscription 在 Fins 调用期间版本或状态变化，按步骤8丢弃 provider result，记录
stale_subscription terminal，不更新 health。若 repository commit 失败则没有 source row，
execution service返回 REPOSITORY_FAILURE，允许同一/后续 attempt 重试。
若terminal transaction观察到Job cancel intent、deadline到期、非leased state或已失lease，返回
job_not_live/lease_lost，零source row/health/outbox；execution service返回SOURCE_INTERRUPTED，随后
PostgresJobStore以自己的cancel/deadline/lease优先级收敛，禁止提交晚到provider结果。

### 6.3 Source terminal row 与 replay

一次 Job 只允许一个真正 producer source_sync_run。idempotency_key：
source-sync-attempt:v1:{job_id}:{producer_attempt_id}

operation首次generation的``acquired_at``精确等于该acquire transaction全NOWAIT锁后的single
``raw_acquire_clock``。takeover必须同时写
``acquired_at=updated_at=GREATEST(raw_acquire_clock,
old_operation.acquired_at + interval '1 microsecond')``，从而即使PG wall clock回拨也满足ACTIVE transition
guard的strict forward progress；generation=1 insert的created_at audit default不替代raw acquired_at。

``source_sync_run.started_at``精确取terminal owner generation的``operation.acquired_at``。terminal全NOWAIT锁后
唯一一次``raw_terminal_clock = clock_timestamp()``既用于live/deadline验证，也唯一派生
``authoritative_terminal_at = GREATEST(raw_terminal_clock, operation.acquired_at,
locked_health_head.observed_at when a head exists)``；不得二次读clock。health head不存在时第三项省略。
``source_sync_run.finished_at``、receipt finished_at、operation terminal updated_at，以及本次推进时的
health head observed_at/updated_at、health snapshot observed_at/created_at、alert outbox created_at都精确写
同一个``authoritative_terminal_at``。run的既有created_at audit default不作为business observation，
不要求与其相等；freshness UTC date同样取``authoritative_terminal_at``的UTC date。
``latency_ms``为``authoritative_terminal_at-started_at``截断到非负整数毫秒。
即使数据库wall clock向后跳或locked health head比operation更新，也保证finished_at>=started_at、head
UPDATE不倒退且同一observation全链时间一致；takeover更新acquired_at，因此不把旧attempt等待时间归给
新producer。operator re-enable没有operation，使用其全NOWAIT锁后single clock精确派生
``authoritative_reenable_at = GREATEST(raw_reenable_clock,
locked_health_head.observed_at + interval '1 microsecond')``，并把head observed_at/updated_at与operator
snapshot observed_at/created_at全部写该值，以满足transition guard strict forward progress；不影响source
run/outbox。

后续 attempt replay 不插入第二条 source run/snapshot/outbox，只返回persisted
``SourceSyncResult``与``SourceSyncAttemptReceipt``。其canonical bytes、SHA、source_sync_run_id、
producer_attempt_id、source_receipt_sha256与首次提交逐字节相同；result/receipt均没有persistent
replay字段，也不得在重放时重建document或改变任一值。重放事实只存在于本次调用的
``SourceOperationAcquireDecision.action=terminal_replay``，不进入Job result、source run或receipt。

source run status 使用既有 closed值：

- succeeded、no_change、partial、skipped_disabled -> succeeded
- failed、stale_subscription -> failed
- domain cancellation -> 不写 row

safe_error_code 唯一映射：succeeded/no_change/skipped_disabled为NULL；partial为partial_batch；
stale_subscription为stale_subscription；failed必须为unsupported_market、unsupported_form、
stale_data、provider_rate_limited、provider_unavailable或fins_invariant之一。records_ingested
精确等于downloaded_count+reused_count，records_discovered精确等于Fins discovered_count。

新row的finished_at与13个core binding/receipt/result字段必须存在；两个既有count保持NOT NULL并与四个
新增count按§8.2求和；safe_error_code按上表允许NULL或closed值，不参与all-or-none。
retry_recommended 是 source observation 字段，不代表 Job READY。

## 7. 健康状态与告警

### 7.1 线性化规则

source_health_states 是每 subscription 唯一 mutable head；version 从1开始。首次无 row视为
healthy / consecutive_failures=0 / version=0，首次 observation 插入 version=1。

``HEALTH_ERRORS``是DDL、domain builder、repository与alert共用的精确闭集：
``partial_batch``、``unsupported_market``、``unsupported_form``、``stale_data``、
``provider_rate_limited``、``provider_unavailable``、``fins_invariant``。它明确不含
``stale_subscription``；该值只属于source observation，永不推进health或进入health/snapshot/outbox。

- succeeded/no_change：healthy、failures=0；
- partial/failed：failures+1；达到 failing_after -> failing，达到 disable_after -> disabled，
  否则 degraded；
- skipped_disabled、stale_subscription、busy、cancel、lease_lost、terminal replay：不变；
- health disabled 不自动恢复，不修改 source_subscriptions.status。

一次真实 provider observation 最多推进一次 version；同 source run replay不得推进。snapshot 与
head CAS 在同一 transaction；snapshot.health_state_version 精确等于新 head version。
若 terminal transaction 观察到当前 health head 已 disabled，任何并发晚到的 succeeded、
no_change、partial 或 failed observation仍保存 source run，但不得自动改变head、写snapshot或alert。

### 7.2 Semantic alert outbox

只在进入/升级 degraded、failing、disabled，或同状态 safe_error_code 改变时写一条 immutable
semantic alert。恢复到 healthy 本 Slice不写 alert。dedupe_key精确使用§3.2.3列出的八字段、固定顺序
canonical transition object与SHA-256算法，不允许此处另减字段或改变顺序。

INSERT ... ON CONFLICT (tenant_id, dedupe_key) DO NOTHING；重复 event 不得回滚 run/snapshot。
outbox的target_status、safe_error_code必须与其五列FK绑定snapshot的status、safe_error_code逐值相同；
SQL FK只闭合tenant/subscription/run/version/snapshot identity，status/error的跨表相等由repository在
同一锁序transaction内构造并在conflict重读时验证，配真实PG negative test，禁止宣称CHECK可跨表。
本表不是 Telegram/Obsidian delivery outbox；物理投递留 Slice 7.6。

### 7.3 Operator re-enable

InvestmentSourcesService.reenable_source_health(scope, request: SourceHealthReenableRequest)：

- repository按subscription -> health head逐行``FOR UPDATE NOWAIT``且全锁成功前零DML；original ``55P03``/
  ``psycopg.errors.LockNotAvailable``在rollback成功时按§6.1精确映射unavailable，rollback failure仍按§9覆盖为
  transaction_aborted，其它SQLSTATE走§9既有矩阵；全锁后只读一次raw PG clock；
- ``source_subscriptions.status``必须精确为``enabled``（这里的operator-enabled只指该既有状态值，
  不存在另一权限字段）；disabled subscription返回health_state_conflict；
- health 必须 disabled 且 version exact；
- 原子置 healthy、failures=0、safe_error=None、version+1，写无 source run 的 operator snapshot；
- 不启用 subscription，不激活 schedule，不写恢复 alert；
- version/status drift 零 mutation。

- records_ingested>0 iff latest_source_observed_date IS NOT NULL；
- succeeded：status=succeeded、safe_error NULL、retry=false、ingested>0、failed=0；
- no_change：status=succeeded、safe_error NULL、retry=false、ingested=0、failed=0；
- partial：status=succeeded、safe_error=partial_batch、retry=true、ingested>0、failed>0；
- skipped_disabled：status=succeeded、safe_error NULL、retry=false、四个count全0；
- stale_subscription：status=failed、safe_error=stale_subscription、retry=false、四count全0；

  对应retry=true，其它false；counts仍满足总和。stale_data可保留verified documents/ingested；
  fins_invariant按§4.1必须documents/counts全空零；provider_unavailable可保留clean-correlated
  failed/ignored counts但ingested=0；其它preflight/transport失败全零。

两个BEFORE INSERT guards只阻止迁移后新legacy shape，不回写或拒绝既有legacy row：

## 10. Startup 与 production composition

既有``_default_provider_or_fail`` admission seam分支保持不变，禁止把external explicit provider偷偷变成
半装配source provider：

- production/integration且``explicit_provider is not None``：先做既有profile/provider admission，随后原样
  返回同一个provider identity；本Slice内部零auto Postgres platform preparation，零source-specific
  FinsService/connector/source service/execution service/handler装配、零descriptor/handler注册、零mapping
  注入，也不对外部provider断言global handler count或四项mapping。既有Host所需
  ``DefaultFinsRuntime``及§4.1要求其eager-owned internal
  ``DefaultFinsWorkerSourceSyncRuntime`` component仍按同一baseline Host construction构造，但不构造/注入
  cross-platform ``FinsService``或Source connector，也绝不注入/改写external provider；caller完整负责其mapping/
  handlers/lifecycle；CLI Worker若需要direct Job/Schedule references，继续遵守既有explicit-provider规则，
  本Slice不改变或从mapping反向猜对象；
- production/integration auto-provider：才进入下列``_build_production_services_provider``完整闭合路径；
- development/in-memory：维持既有profile行为，不伪造production source handler。

auto-provider ``_build_production_services_provider`` 的顺序固定：

1. 构造所有既有Postgres stores、unsealed descriptor/execution registries与runtime adapters；
2. 先用这些依赖构造``JobService``（registry尚可注册但绝不发布），再以它作为
   ``ScheduleJobGatewayProtocol``构造``ScheduleService``；
3. 在既有 DefaultFinsRuntime 与同一 Host 上构造唯一 FinsService；把它仅以
   FinsWorkerGatewayProtocol 注入 FinsSourceConnector；不得创建第二 runtime/repository set；
4. 以同一platform session factory精确构造``PostgresSourceSyncRepository(session_factory)``与
   SourceConnectorRegistry，再把已构造的JobService/
   ScheduleService narrow gateway与source repository注入``InvestmentSourcesService``；独立构造依赖
   source repository+connector registry的``SourceSyncExecutionService``，再构造只依赖其private
   protocol的source handler；禁止late binding、optional setter或构造未闭合对象；
5. register_descriptor(source descriptor)，随后register_handler(source descriptor, exact handler object)；
6. seal descriptor registry，再 seal execution registry；
7. 断言descriptor_count==handler_count==len(EXPECTED_PRODUCTION_HANDLER_BATCH)==1，并验证source
   descriptor lookup与exact handler object identity；
8. 最后一次性发布exact四项mapping。任何前序构造/register/seal/assert失败都按已成功构造的逆序close，
   绝不发布partial mapping。

auto-provider production mapping 精确四项：investment_identity、investment_sources、durable_jobs、
durable_schedules。空/缺 Fins runtime、重复 handler、drift、seal 后注册、mapping漂移都必须在
Worker/Scheduler启动前失败并逆序关闭。acceptance分别证明auto分支exact四项/one source handler，及
explicit provider object/mapping/registries identity逐项未改变且内部source-specific constructor/register
trap零调用（existing DefaultFinsRuntime及其eager internal component仍构造，且单独identity assertion通过）。

## 16. 已知 residual

1. Provider读取不是exactly-once；Fins本地document identity和source operation阻止重复可信副作用。
2. source terminal与Job terminal不是同事务；最后attempt crash可能让Job envelope失败而source truth成功。
   handler返回completion后的Worker cancellation后置门也可能把envelope收窄为HANDLER_REJECTED；两者
   都保留原canonical source truth且重放不加marker。反向地，source从未提交而Job已终结时，operation
   仅保留ACTIVE物理审计；本Slice不提供或持久化其public effective projection；
3. Redis wakeup可丢、重复、乱序；PG claim和source operation仍是真源。
4. 自动health disabled不停止schedule创建no-op Job；operator可显式disable schedule。
5. RSS/industry/manual connector仍不可执行；真实采集在后续Slice。
6. semantic alert只持久化，Telegram/Obsidian投递留后续Slice。
7. Fins现有date-only元数据只能做calendar-day freshness，不能声称分钟级时效。
8. Source execution对同步repository的owned-thread reap保证不会主动遗弃仍运行的thread，且terminal PONR后
   durable repository decision优先，但不提供wall-clock上界：若SQLAlchemy/psycopg/OS connect、pool、network
   或statement永不返回，outer coroutine与graceful Worker drain也会无限等待。``FOR UPDATE NOWAIT``只界定
   row-lock contention，不是connect/network/statement timeout。本Slice不扩大scope修改全局engine/session
   timeout，也不得用``asyncio.wait_for``后遗弃仍运行的thread或新造全局timeout；后续platform reliability
   gate必须把bounded pool/connect/statement/network timeout变成可执行配置和故障验证门禁。
9. Job/Schedule既有repository failure surface没有typed code，因此Source public facade只能稳定暴露
   ``unavailable``，不能区分infra failure与persisted drift。若后续operator observability要求公开区分，归入
   独立typed repository-error contract work unit；不得在本Slice按message补诊断。

    mismatch可能使非空开发库upgrade fail closed。这是保真优先的明确admission，不是数据丢失或兼容读取。需要保留此类row时，
    owner为后续独立legacy identity migration/public unavailable work unit；当前Item 6不得自行放宽。
