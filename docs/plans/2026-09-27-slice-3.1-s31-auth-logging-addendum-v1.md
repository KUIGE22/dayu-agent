## 3. 可直接实现的修复契约

1. `create_platform_engine(dsn)` 保留签名和 `echo=False`，精确使用 `create_engine(dsn, echo=False, hide_parameters=True)`；更新 docstring 说明不在 SQLAlchemy Engine 日志或其 DB 异常文本展示 bind 值。该设置覆盖平台全部受控 Engine，不依赖调用方 logger 级别。
2. `authorize_active_actor` 与 `authorize_reviewer` 保留签名、token-derived 见证及动作各一条授权 SELECT。先核已有 `Session` 事务，取得**本次事务同一** `Session.connection()`，检查其 `Connection.engine.hide_parameters is True`；若否则抛固定 `EvidenceReviewStorageError`，不执行 hash-bound SQL。`SET LOCAL`、readback、动作授权 SELECT 都在这一个已核参数隐藏的 `Connection` 上执行，避免检查一个 bind 而在另一个 bind 上发查询。该 Connection 属于调用方 Session 事务；helper 不提交/回滚、不缓存它。SQLAlchemy 连接/查询故障仍在 `except` 结束后转固定错误，不能沿 `__context__`/`__cause__` 暴露 bound hash。
3. hash 可在连接检查前于内存形成，但不得进入 SQL bind、logger、错误或文件，直到本次 Connection 已通过隐藏参数检查。`SET LOCAL` 的 tenant hint 仍非身份来源，RLS readback 和 READ COMMITTED 检查必须先于动作授权 SELECT；无匹配仍统一 unauthorized。异常后由调用者事务管理器回滚。
4. 不声称能防止可信进程内自定义 DBAPI/event hook 主动读取参数；可信 app-role 进程与 Session 提供者仍是现有边界。普通 SQLAlchemy Engine INFO 参数记录必须被实际阻断，而不是只写 README 约定。
