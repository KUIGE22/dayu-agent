## 5. 新入口完整算法与错误

1. _tenant_hint(scope_hint)：exact TenantScope/TenantId、canonical非nilUUIDhint；这是RLS定位，不是actor。
2. _token_hash(raw_token)：exactbytes/43-character unpadded ASCII base64url、decode32byte+重新编码相等；仅temporary SHA256hex用于bind。形态非法统一unauthorized，不回显raw/hash/decodererror或cause/context。
3. 使用调用者已经开启的同一个Session事务；_checked_connection验证session.in_transaction、Engine.hide_parameters=True。不调用begin/commit/rollback，不换连接。
4. _set_tenant_context在同connection SET LOCAL app.tenant_id并readback，必须READ COMMITTED；assigned/hint/isolation不符storageerror，事务外usageerror。
5. 同一_granted_auth_row SELECT核t/u/o active、expires_at非NULL且严格>statement_timestamp、tokenhash等值、tenant整条RBACjoin相等、固定Factpermission；ORDER BY ur.id,rp.id,p.id LIMIT1保持。token→user/tenant与grant由同query推导，没有第二SELECT拼actor/grant。
6. 新入口先要求len(row)==8，否则EvidenceReviewStorageError；_AuthRow列精确为0tenant、1user、2token、3checked_at、4user_role、5role、6role_permission、7permission。每UUID通过现有_required_uuid（真实UUID且非nil）；checked_at通过_checked_at归UTCaware。构造FactPromoterAuthWitness全部字段，policy_key=FACT_PROMOTION_PERMISSION_KEY，不含raw/hash。新增长度检查仅此入口，不改变旧actor/reviewer的投影处理规则。
7. SQLAlchemyError离开except后抛现有EvidenceReviewStorageError，避免保存参数异常context/cause；现有EvidenceReviewUnauthorizedError/UsageError/StorageError原样传播。不catchBaseException/KeyboardInterrupt/SystemExit/async cancellation为unauthorized，不catch未知Exception掩盖程序错误。

固定错误类型/文本仍为：EvidenceReviewUnauthorizedError="认证或授权失败"、EvidenceReviewStorageError="认证存储失败"、EvidenceReviewUsageError="认证事务无效"。不新增code enum、不泄露DSN/SQLbind/内部message。缺grant与token/user/org不存在或失效不可区分；角色与permission引用被撤销仍统一unauthorized；queryrow非法UUID/UTC视为owner存储错误，不转业务授权失败。

## 6. Snapshot撤销与并发规则

授权以这一个Factpermission SELECT的READ COMMITTED statement snapshot为判定边界；checked_at沿用statement_timestamp()表示语句开始，不冒称精确snapshot获取时刻或commit可见时刻。撤销在该snapshot之前提交、或expiry在该语句开始时刻已到期→拒绝；SELECT后另连接提交撤销不会追溯抹掉已返回witness；同事务下一次helper SELECT必须重新读snapshot并拒绝。不是transaction_snapshot、不是commit clock，也不保证任意后续side effect/commit时仍有grant。

不增加FOR SHARE/FOR UPDATE/tablelock/advisorylock/SECURITYDEFINER或ACL。旧app对user_roles/role_permissions有SELECT/INSERT/DELETE、无UPDATE；row-lock语法可能要求额外UPDATE权限，而且会改变已接受撤销模型。并发revoker不能被helper持锁阻塞到commit；使用真实第二连接验证撤销可在helpercaller事务仍开启时完成。

permissionkey变更、user_role/role_permission删除、tokenstatus/expiry、user/orgstatus是现有实际可撤销路径；helper不添加指向grant的持久审计FK或缓存。返回typedwitness之后的futureB1应在Fins前/写入前/锁等待后fresh授权，并保存历史grant快照而不阻塞删除；本Authunit不实施这个future事务。
