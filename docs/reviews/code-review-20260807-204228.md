## 审查发现 (Findings)

### Finding L-01: `format_utc` 对 naive datetime 缺少防御性测试

- **Severity**: LOW
- **Dimension**: Correctness / Test Coverage
- **Evidence**:
  - `format_utc` 不检查 `value.tzinfo` 或 `value.utcoffset()`，对 naive datetime 调用 `value.astimezone(UTC)` 会按 Python 默认行为（假定为本地时间）转换，与 `format_utc_seconds` 的显式 `raise ValueError("now must include a timezone")` 行为不同。
  - 此差异在 plan §1.6.4 中声明为刻意设计（microseconds 族继承原有行为），但当前测试未固定该行为。
- **Risk**: 若 Slice 2A/2B 迁移时误把 naive datetime 传给 `format_utc`，不会触发异常，可能产生未预期的 UTC 时间。
- **Recommendation**: Slice 1 commit 前或 Slice 2A migration 前增加 `format_utc` 的 naive datetime characterization test，锁定当前"接受 naive datetime 并转换为 UTC（假定 local time）"的行为（或评估是否应统一加 tz-aware 检查）。

### Finding L-02: `_MissingOffsetTimezone` 测试 helper 的 `utcoffset`/`dst` 返回类型标注为 `-> None`

- **Severity**: LOW
- **Dimension**: Type Precision (test-only)
- **Evidence**:
  - `tzinfo` 协议中 `utcoffset` 期望返回 `timedelta | None`，`dst` 期望返回 `timedelta | None`。
  - 测试类标注为 `-> None`。运行时返回 `None`（`return` 无表达式），语义正确。
- **Risk**: 不影响生产代码，且 pyright 对测试文件报 0 errors。
- **Recommendation**: 可忽略或将返回类型改为 `timedelta | None`。

### Finding L-03: `decode_base64_strict` 缺少 `TypeError` 捕获（设计刻意，无风险）

- **Severity**: LOW (OBSERVATION, not defect)
- **Dimension**: Correctness
- **Evidence**: `decode_base64` 族 A 捕获 `(binascii.Error, TypeError, ValueError)`，但 `decode_base64_strict` 族 B 仅捕获 `(binascii.Error, ValueError)`。因 shared 版 `text: str` 限定入参类型，`base64.b64decode(str, validate=True)` 理论上不应产生 TypeError，但族 B 的私有实现 `manual_recovery._decode_base64` 的入参是 `object`，其缺少 TypeError 捕获是有意义的差异。
- **Risk**: Slice 2B 迁移 `manual_recovery._decode_base64` → `decode_base64_strict` 后，调用方 `_required_text` 预处理会将入参收窄为 `str`，TypeError 路径自然消除。
- **Recommendation**: 无。当前行为与 plan C5-CTRL-03 一致，是刻意保留的族 B 特征。

1. **Slice 2 迁移是主要风险源**: 本 slice 本身无已知缺陷，但 19 个文件的 call-site 迁移 (Slice 2A/2B) 是 shared helper 正确性的真正验证。若 call-site adapter（`dict(require_mapping(...))`, `fingerprint_str(dict(value))`）使用不当，可能引入行为差异。

3. **`_MissingOffsetTimezone` 在 Python 3.11 上的行为**: 此测试 helper 依赖 `tzinfo` 协议，在 Python 3.11 和 3.13 上行为应一致（`utcoffset` 返回 `None` 是标准协议）。已在 3.13 上验证通过。
