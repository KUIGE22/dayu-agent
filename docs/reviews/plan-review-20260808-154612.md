## 1. 分析与裁决

### 1.1 Configured full-rule multiset vs `--select ALL`

| 维度 | configured default | `--select ALL` |
|---|---|---|
| 规则类 | E + F（约 2 类） | 全量（数十类） |
| 典型 violation 数量级 | 数千（代码风格 + 未使用导入等） | 数万（含 type annotation、docstring、security 等） |
| CI 执法 | 不在 PR gate 中 | 不在任何 CI 中 |
| 项目实际使用 | pyproject.toml 无 select → default | 从未配置 |

**裁决**: 用户所称 "full-rule positive 192" 中的 "full-rule" **不是** `--select ALL`，也不是 configured default（E+F）。192 这个数字的精确来源在当前证据下**无法独立验证**——我被阻止运行额外 Ruff 命令。可能的来源：
- 对特定子目录运行的 E+F 规则
- 对 `--diff`（仅 PR delta）运行的 E+F 规则
- 对特定规则子集（如仅 F 类）运行的结果

**结论**: 证据不足以确定 192 的精确语义。但可以确定的是：**它不是 `--select ALL` 的结果**，因为 configured rule set 是 E+F default。

### 1.2 当前架构 refactor 引入 vs 早期 feature branch 债务

**无法在不运行 `git log --diff-filter` + 逐 commit ruff 的前提下精确区分。** 但以下结构性事实成立：

1. 分支 30+ commits 中，早期 commits（Slice 1–10）建立了 dual-model research 基础设施（utils/、tests/），后期 commits（Slice 11–13）是 CLI write architecture refactor。
2. 438 files changed 的主体是 feature branch 全生命周期的增量，不是单一 refactor 引入。
3. CI 从未对全仓运行 Ruff，因此 **无论哪个阶段引入的 violations 都从未被拦截**。

**裁决**: 192 positive（无论其精确语义）是 **整个 feature branch 的累积债务**，不能归因于单一 refactor 阶段。将其定性为 "当前架构 refactor 引入" 缺乏证据。

### 1.3 origin/main 正增量是否 PR residual

**是。** PR 合并时，CI gate (`CI PR Required`) 仅检查 pyright + pytest。Ruff 不在 gate 中。因此：

- PR 的 Ruff 正增量（相对于 origin/main）**不会阻止合并**
- 这些正增量构成 **PR 级 residual**，应在 aggregate deepreview 中如实暴露
- v5.6 plan 的 "Ruff delta" 正是为此设计——信息性测量，非阻断性门禁

### 1.4 Ratchet Baseline 选择

| 选项 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|
| `origin/main` (`2115c86`) | 精确测量 PR 全量增量 | 包含早期 research 代码的 violations，不纯是 refactor | PR 级 deepreview |
| 首个 refactor commit (`5821014`) | 隔离 refactor 阶段增量 | 需要精确定义 "refactor 起点"；且早期 commits 也是 feature branch 一部分 | refactor-scoped review |
| `HEAD~1` (`2a4bafb`) | 仅看 v5.6 plan commit 增量 | 太窄，v5.6 只是 plan 文本更新 | 不推荐 |

**推荐**: 以 `origin/main` (`2115c86`) 作为 ratchet baseline。理由：
1. PR 的 gate 语义是 "合并到 main 后引入什么"，baseline 应是 main
2. 早期 research 代码的 violations 也是 PR residual 的一部分
3. 若需隔离 refactor 阶段，可额外运行 `git log --oneline origin/main..HEAD -- dayu/cli/ utils/` 并逐 commit bisect，但这超出本次审查 scope

## 5. 可执行算法（供 Controller 后续使用）

```
ALGORITHM: ruff-gate-ratchet
INPUT: base_ref = origin/main, head_ref = HEAD
OUTPUT: violation_delta, residual_report

1. STASH working tree changes
2. CHECKOUT base_ref
3. RUN ruff check → capture base_violations (count)
4. CHECKOUT head_ref
5. RESTORE stash
6. RUN ruff check → capture head_violations (count)
7. delta = head_violations - base_violations
8. IF delta > 0:
     REPORT "Ruff residual: +{delta} violations vs {base_ref}"
     CLASSIFY as aggregate deepreview residual (非 gate blocker)
9. ELSE:
     REPORT "Ruff delta: clean (no new violations)"
10. OPTIONALLY: run ruff check --select ALL for informational comparison
     (注意: 结果与 configured default 不同，仅作参考)
```
