## 已验证的假设

1. **S15-ERR-03 已闭合**：S15-CTRL-15.3 将 bundle owner 固定为 canonicalization 唯一 owner，要求 descriptor reference 为 canonical absolute raw string，并固定 `raw -> relative locator -> bytes` 的不可变映射；reader 仅 `str(path)` exact lookup、零 filesystem I/O，reader-mode 禁止 `resolve()`，package asset 明确不进入 mapping。该合同与当前 builder 对 artifact 使用 `str(path.resolve())` 的事实相符（`_research_template_bundle.py:97-120`）；source-write-manifest 的非规范历史输入会在本 slice strict closure 中 fail closed，而不改变 `content_reader=None` 公共路径。
2. **S15-ERR-01 已闭合**：S15-CTRL-15.5 不再要求不可能的 whole-function AST exact，改用 reader=None golden return/error/warning、filesystem call order/count 与下游参数；S15-CTRL-15.6 已存在且覆盖五个 reader 分支、zero ordinary source-tree I/O、package assets、unknown/noncanonical key、regular replacement、FD `BaseException` close、Linux/macOS 及 default-reader corpus。
3. **root capability 的原始身份绑定已闭合**：S15-CTRL-15.2 要求从 filesystem root FD 逐段 `O_DIRECTORY|O_NOFOLLOW` 打开、最终 root FD 的 `fstat` 与 preflight `lstat` 的 `(st_dev, st_ino, mode)` exact，并禁止按 root pathname 重开。当前实现的 root `os.open(resolved_source_root, O_RDONLY|O_DIRECTORY)` 缺少该保护（`_research_template_bundle.py:548`），故此 delta 是必要且方向正确。当前 Darwin 环境存在 `O_DIRECTORY`、`O_NOFOLLOW`，且 `os.open` 支持 `dir_fd`；计划也将 Linux/macOS flags/`dir_fd` 结构列入矩阵。
4. **neutral leaf 与 default path 的分层已闭合**：owner 到 neutral leaf 的单向依赖、optional keyword-only 透传、None 原行为、package-asset bypass 均已明确；不需要复制 parser/validator 或引入跨层 filesystem framework。

## Findings

### S15-ERR-02-未修复-[高]-leaf-before-read 的 snapshot 时序自相矛盾，未定义 descriptor-first 与成员身份绑定
- **位置**: S15-CTRL-15.2 “在读取任一 bytes 前先打开全部 leaf FD”及“member directory/leaf replacement 均不得改变本次 capability”；S15-CTRL-15.6 replacement matrix。
- **问题类型**: 不可直接实施 / 契约缺失 / 并发恢复风险 / 测试缺口。
- **当前写法**: 计划要求 descriptor 与全部 member 相对唯一 root FD 打开，并在读取任一 bytes 前打开全部 leaf FD；同时要求 root/member replacement 不得改变本次 capability，失败时 fail closed。
- **反例/失败场景**: closure 的成员名称在 descriptor payload 内，故实现必须先打开并读取 descriptor 才能知道要打开哪些 artifact/source-write-manifest FD。当前源码也先 `_load_json_object_no_follow(resolved_bundle, ...)`，随后才 `_enumerate_closure_reference_paths(payload)`（`dayu/cli/commands/_research_template_bundle.py:740-755`）。因此字面“任一 bytes 前全部 leaf”无法实施；若实现者把 descriptor 排除在“任一 bytes”之外，却未把 descriptor FD 的身份、读取、payload parse 与后续全部 member-FD 打开明确成受控两阶段，snapshot 起点会由实现者自行选择。攻击者可在 descriptor parse 与某个尚未打开的 member 之间替换该 member 或其目录：root FD 仍正确、`O_NOFOLLOW`/regular `fstat` 仍成功，但本次 inspection 接受的是替换后的 inode，既非已声明的初始 leaf FD，也非明确拒绝。现有 “任一 open/identity 失败”没有规定 member/component 的 preflight identity record 与 FD `fstat` exact comparison，无法拒绝该情形。
- **为什么有问题**: S15-ERR-02 要解决的不只是 root pathname swap，而是把本次 closure 所消费的实体确定为同一 capability snapshot。root original `lstat` identity 只能固定 root；它不能固定尚未打开的 member。S15-CTRL-15.6 又要求 member-directory/leaf replacement 后“只来自初始 root/leaf FD 或明确拒绝”，但当前文字没有可执行的 snapshot boundary 或判定规则。实现 agent 将不得不在安全语义、FD 生命周期和测试 oracle 上重新设计，不能满足 code-generation-ready。
- **直接证据**: 当前 `inspect_research_template_bundle_closure()` 的 descriptor-first 顺序见上述 `:740-755`；current `_open_regular_no_follow()` 也是一次只打开一个 leaf、读取后关闭（`:522-607`），正是本 delta 要替换的基础。计划 §15.2 对 root 明确写出 preflight `lstat` identity exact，却只对 leaf 写“`fstat` regular”和“先打开全部 leaf FD”，没有 member/component identity 的记录/比较，也没有 descriptor-first 例外、其 byte-read 时点与 close ownership。
- **影响**: 实施 Agent 跑偏 / source-tree snapshot 不可验收 / replacement matrix 不能证明目标 / trust-boundary 风险后移。
- **建议改法和验证点**: 将 §15.2 写成可执行的两阶段合同：（1）从已绑定 root FD 打开 descriptor leaf FD，立即以预检记录 `(st_dev, st_ino, mode)` exact 绑定；仅从该 FD 读取/解析 descriptor bytes，且保持 FD 由同一 `ExitStack` 持有；（2）按该 immutable payload 作纯 lexical reference canonicalization，逐段 no-follow 打开所有 member，记录/比对每个预检 component 与 leaf 的 identity；只有当全部 member FD 已打开且验证后，才读取 member bytes，并用这些 FD 形成 snapshot。明确 snapshot point、descriptor 是否为 snapshot entry、任何 identity mismatch 的稳定错误，以及所有阶段在 `BaseException` 下的 exact close 顺序。矩阵应分别在 descriptor read 前后、reference enumeration 后、每个 member FD 打开前后注入 directory/leaf replacement，断言仅初始已绑定 FD bytes 或稳定拒绝，且普通 source-tree I/O 为 0。
- **修复风险（低/中/高）**: 中。
- **严重程度（低/中/高/严重）**: 高。
