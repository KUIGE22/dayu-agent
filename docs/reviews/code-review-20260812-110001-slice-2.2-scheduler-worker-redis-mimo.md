## Findings

### 1-L-未修复-低-`_reject_nonfinite` 错误消息丢失诊断信息

- **入口/函数**: `decode_redis_wakeup_message` → `json.loads(..., parse_constant=_reject_nonfinite)`
- **文件(行号)**: `dayu/host/redis_wakeup.py:677`
- **输入场景**: Redis 消息包含 `NaN` 或 `Infinity` JSON token
- **实际分支**: `_reject_nonfinite(value)` 被 `json.loads` 的 `parse_constant` 回调触发
- **预期行为**: 错误消息应包含触发该回调的实际 token 值
- **实际行为**: `value[:0]` 对任意字符串返回空字符串，最终消息为 `"nonfinite redis wakeup token: "`，不携带任何诊断信息
- **直接证据**: `redis_wakeup.py:677` — `raise ValueError(f"nonfinite redis wakeup token: {value[:0]}")`
- **影响**: 运维日志无法区分 NaN/Infinity/其它非有限 token，增加现场排查难度。不影响正确性（消息仍被拒绝）。
- **建议改法和验证点**: 改为 `value[:64]` 或直接使用 `value`（JSON token 通常很短），保留截断防止异常超长输入
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 2-L-未修复-低-Worker 中 tenant-mismatch 防御为不可达死代码

- **入口/函数**: `PlatformWorker._consume_redis_read`
- **文件(行号)**: `dayu/host/worker.py:1403`
- **输入场景**: tenant_id 不匹配的 WAKEUP hint 到达最终 guard
- **实际分支**: `decode_redis_wakeup_message`（`redis_wakeup.py:556`）已验证 `tenant_id != expected_tenant_id` 并返回 `None` → `get_message` 返回 `INVALID_MESSAGE`。到达 L1403 时 tenant 已保证匹配。
- **预期行为**: 该 guard 应标记为已知冗余防御或移除
- **实际行为**: `str(hint.tenant_id) != self.scope.tenant_id.value` 检查在正常路径不可达；仅当 `str(UUID)` 格式化与 `scope.tenant_id.value` 结构性分歧时才触发（不可能）

- **影响**: 无正确性影响。代码可读性轻微降低，可能误导后续维护者认为此处有实际防御职责。
- **建议改法和验证点**: 移除或加注释标记为 defense-in-depth
- **修复风险（低/中/高）**: 低
