### S23-I5-C7-01-未修复-[高]-ACTIVE takeover 没有把持久化 snapshot 锚定到 durable payload/available_at，可执行移位查询窗口

- **入口/函数**: `PostgresSourceSyncRepository.acquire_operation()` -> `_decide_existing_operation()` -> `_disposition_for_snapshot()` / `_binding_disposition()`。

- **实际分支**: `_decide_existing_operation()`只验证 operation outer tenant/job/subscription/payload SHA、snapshot 自身 canonical SHA，以及 embedded binding 的 tenant/subscription；它没有比较 `ManualSourceSyncPayload.execution_snapshot`，也没有用 locked `job_runs.available_at`验证 scheduled window。随后 `_binding_disposition()`只比较 `snapshot.binding` 与 current binding，完全不读取 query dates；同 binding 的移位 snapshot 因而得到 `READY`。代码推进 generation/owner 并把该 snapshot 原样作为 `ACQUIRED` decision 返回。
