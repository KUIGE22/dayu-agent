## New Findings (本轮新增)

### NN-1 | 未修复 | 严重度: HIGH | `asyncio.shield` 在重复取消时不能保证 worker 完成

**位置**: v3 §7 `_finish_run_async` 实现, §11 取消传播

**问题类型**: Python asyncio 语义理解错误

**当前写法** (v3 §7):
```python
try:
    await asyncio.shield(release_task)
except asyncio.CancelledError:
    await asyncio.shield(release_task)
    raise
```

**v3 声称** (§6):
> 重复 `task.cancel()`：第二次 cancel 在 catch 块的 `shield(release_task)` 中被 shield 阻挡 → worker 完成 → re-raise ✓

**实测反证**:
```python
# Python 3.13 实测：重复 cancel 时 shield 不能阻挡外层 CancelledError
results = []
async def outer():
    task = asyncio.create_task(inner_task())  # 0.5s sleep
    try:
        await asyncio.shield(task)
    except asyncio.CancelledError:
        results.append('caught_first')
        await asyncio.shield(task)  # ← 第二次 cancel 在此抛 CancelledError
        results.append('after_second')  # ← 永远不会执行
        raise

outer_task = asyncio.create_task(outer())
outer_task.cancel()  # 第一次
outer_task.cancel()  # 第二次（在 catch 块的 await 点）
# 结果: ['caught_first', 'outer_cancelled']
# inner_task 仍在后台执行，但 outer 未等待它完成
```

**直接证据**:
- `asyncio.shield` 只保护 inner task 不被取消，不阻止 outer task 的 `await` 点抛 `CancelledError`
- 每次 `task.cancel()` 增加 cancel counter，每次 `await` 检查 counter > 0 则抛 `CancelledError`
- catch 块中的 `await asyncio.shield(release_task)` 仍是 `await` 点，可被再次 cancel

**影响**:
- 若外层 task 被重复取消（如多个取消源），`release_task` 可能未完成就返回
- 资源清理不完整：`bridge.stop()` 可能未执行
- 虽然 daemon 线程不阻止进程退出，但 permit 可能泄漏

**建议改法**:
```python
async def _finish_run_async(self, *, bridge, deadline_watcher, permits, run_id):
    release_task = asyncio.create_task(
        asyncio.to_thread(self._finish_run, bridge=bridge, ...)
    )
    try:
        await asyncio.shield(release_task)
    except asyncio.CancelledError:
        # 等待 worker 完成，忽略后续取消
        while not release_task.done():
            try:
                await asyncio.shield(release_task)
            except asyncio.CancelledError:
                continue
        raise
```

或使用 `task.uncancel()` (Python 3.11+):
```python
except asyncio.CancelledError:
    asyncio.current_task().uncancel()
    await asyncio.shield(release_task)
    raise
```

**验证点**:
```python
async def test_repeated_cancel_still_waits():
    # 取消 outer_task 多次，验证 bridge.stop() 仍被调用
```

**修复风险**: LOW — 使用循环或 `uncancel()` 即可

**严重度**: HIGH — 资源泄漏风险，与 F-8/NF-4 的核心承诺矛盾

**标签**: `accepted-candidate`

### NN-3 | 未修复 | 严重度: MEDIUM | 外部 observer 线程异常不传播

**位置**: v3 §9 测试代码

**问题类型**: 测试基础设施缺陷

**当前写法**:
```python
def external_observer() -> None:
    assert bridge.stop_started.wait(timeout=5.0), "bridge.stop() 未在超时内调用"
    loop.call_soon_threadsafe(callback_executed.set)
    callback_executed.wait(timeout=2.0)
    bridge.release_stop.set()

t = threading.Thread(target=external_observer, daemon=True)
t.start()
# ...
t.join(timeout=5.0)

assert callback_executed.is_set(), "..."
```

**问题**:
1. 如果 `bridge.stop_started.wait(timeout=5.0)` 超时，`assert` 在线程内失败，但异常不会传播到主测试线程
2. `t.join(timeout=5.0)` 只等待线程结束，不检查线程内异常
3. 如果线程 hang（`release_stop` 未 set），`t.join` 超时后测试继续，可能误判

**反例**:
```python
# 场景：bridge.stop() 未被调用（实现 bug）
# → stop_started.wait(5.0) 超时
# → assert 失败，线程抛 AssertionError
# → t.join(5.0) 返回（线程已退出）
# → callback_executed.is_set() 为 False
# → 测试 FAIL，但错误信息是"回调未执行"，不是"bridge.stop() 未调用"
```

**影响**:
- 测试失败时错误信息不准确
- 难以定位根因

**建议改法**:
```python
# 使用 threading.Event + exception 传播
observer_error = None

def external_observer() -> None:
    nonlocal observer_error
    try:
        assert bridge.stop_started.wait(timeout=5.0)
        loop.call_soon_threadsafe(callback_executed.set)
        callback_executed.wait(timeout=2.0)
        bridge.release_stop.set()
    except Exception as e:
        observer_error = e
        bridge.release_stop.set()  # 确保不 hang

t.join(timeout=5.0)
assert observer_error is None, f"Observer thread error: {observer_error}"
```

**验证点**: 故意让 bridge.stop() 不被调用，验证测试能报告正确错误

**修复风险**: LOW — 简单的异常捕获

**严重度**: MEDIUM — 测试可调试性

**标签**: `accepted-candidate`

## 最终结论

**FAIL — 存在 2 个 HIGH 严重度 finding 未关闭**

1. **NN-1 (HIGH)**: `asyncio.shield` 在重复取消时不能保证 worker 完成。v3 的 catch 块中 `await asyncio.shield(release_task)` 仍是 cancellation point，重复 cancel 会抛出 `CancelledError` 而不等待 worker。这与 v3 §6 声称的"第二次 cancel 被 shield 阻挡"矛盾，实测已证实。

2. **NN-4 (HIGH)**: `uv run` 未指定 `--python 3.11`，实际使用 `.venv` 中的 Python 3.13。测试/验证环境与生产要求的 3.11 不一致。

**建议**:
1. 修复 NN-1: 使用 `while not release_task.done(): try: await shield(release_task); except CancelledError: continue` 循环，或在 catch 块开头调用 `asyncio.current_task().uncancel()`
2. 修复 NN-4: 所有 `uv run` 命令添加 `--python 3.11`

**可带风险继续的前提**:
- 修复 NN-1（资源泄漏是正确性问题）
- 修复 NN-4（环境一致性）
- 接受 NN-2 的风险（diff review 弥补测试缺口）
- 接受 NN-3 的风险（测试可调试性降级）
