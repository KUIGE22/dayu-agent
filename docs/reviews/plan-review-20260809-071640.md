## 2. 回归核验结果

### 2.1 materialization 输入闭包（重点）

只读枚举得到 `dayu/assets/` 实际内容：根级 `定性分析模板.md` + `research_templates/`（`README.md`、`common/consumer/cyclical/financial/technology` 各自的 `.md` 与 `.definition.json`）。

全仓 `resolve_package_assets_path()` 消费点共 6 处，全部落在这两个闭包内：

- `research_template_assets.py`：`<assets>/research_templates`（模板 `.md`）与 `<assets>/定性分析模板.md`（`build_composed_research_template_text` 同时读 `common.md` + `technology.md` + 根级 base template）；
- `research_template_definitions.py`：`<assets>/research_templates` 下的 `*.definition.json`；
- `commands/_research_template_helpers.py`、`commands/research_workbook.py`：同一 `research_templates` 目录；
- `dependency_setup.py`：`<assets>/定性分析模板.md`；
- `commands/init.py`：整个 assets 根（复制场景，非本 run 路径）。

`build_research_template_package_manifest()`（`commands/_research_template_core.py:782-812`）经 `list_research_templates()` 枚举目录内除 README 外全部 `.md`，并对每个模板调用 `build_monitoring_rules_payload` / `build_monitoring_source_map_payload`，后者经 `load_research_template_definition`（:34、:178）读取同名 `.definition.json`。因此 `consumer.md` 等非 AAPL 模板确实进入 manifest 输入，plan:113 把它们纳入闭包与代码事实同源，**不是过度扩张**。

结论：闭包**闭合**，无遗漏消费点。

### 2.2 config tree 与 asset tree 分离

plan:112 只约束 `resolve_package_config_path()` 的 canonical tree（含 scene manifests，单列关键文件明示为“诊断分解，不是替代 tree 的不完全 allowlist”）；plan:113 独立定义 research asset 闭包。两者在 receipt（:114）、run 身份（:250）、drift stop（:329、:586）与 live gate（:642、:644）中始终并列且不混用同一 fingerprint。分离**成立**，未见跨层耦合。

### 2.3 drift fail-closed

plan:250 把两个 tree 与根级 base template 都纳入 run-id 生成输入；:329、:586、:587 要求漂移在 subprocess 前失败；:308 的 Slice 1/2 测试契约逐项列出 base template、`technology.definition.json`、`common.md`、`technology.md` 与「任一其它会被 package manifest 枚举/消费的 research asset（例如 `consumer.md`）」五类变更必须改变闭包指纹并触发 drift fail。测试断言覆盖面与闭包定义同源，**无 gap**。

### 2.4 `verify` 模式互斥

plan:323 定义两种互斥模式（fixture 只接 `--fixture`；live 必须同时接 `--plan` + `--fingerprint`），并要求同传、缺 plan、缺 fingerprint 三种情形在读取产物前 fail closed；:332 给出对应的四条 CLI 参数测试（两条 happy path + 三条 fail-closed）。OQ-B **已收口**。
