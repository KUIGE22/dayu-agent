## 9. Adversarial Failure Pass

### 9.1 闭包 #1 label 语义

**挑战**: application runner 的 partial 不绑定 `run_label`，使用默认值 `"configuration-application"`。这是否正确？

**分析**: 原始 `write.py` 中的嵌套 `_snapshot_builder` 也不传递 `run_label`，因此使用同一默认值。行为保持。✅

### 9.2 Rollback/Manual-Recovery-Application 默认 label

**挑战**: rollback 和 manual-recovery-application 使用默认 label `"configuration-application"`，但这些不是 application 操作。label 是否误导？

**分析**: 原始代码中这些 runner 的嵌套 `_snapshot_builder` 也不传递 `run_label`，使用同一默认值。label 仅用于日志，不影响功能。行为保持。✅（Low observation，非 finding）

### 9.3 `_build_snapshot_for_args` 必要性

**挑战**: `_build_snapshot_for_args` 是 `_build_fresh_application_routing_snapshot` 的薄包装，是否违反"禁止胶水 seam"？

**分析**: 此函数不是兼容性 wrapper——它是新设计的一部分，为 `build_snapshot_builder` factory 提供干净的回调接口。函数有独立的类型签名和 docstring。✅

### 9.4 `getattr` 使用

**挑战**: `_run_write_model_configuration_application` 中使用 `getattr(args, "...", "")` 读取参数。这是否违反 AGENTS 零 `getattr` 约束？

**分析**: 这是从旧代码忠实迁移的行为。`args` 类型为 `argparse.Namespace`，这些字段可能不存在。在 Slice 10 引入 `DayuCliArguments` 之前，`getattr` 是读取可选 argparse 字段的标准方式。Slice 6 使用当时已存在的 `argparse.Namespace`，符合计划 §4.8 S6-CTRL-01。✅

### 9.5 测试覆盖未命中行

**挑战**: `_write_config_application.py` 有 2 行未覆盖（95.92%）。是什么？

**分析**: 实现记录未列出具体行号，但覆盖率远超 80% 门槛。未覆盖行可能是异常分支中的 unreachable 路径或日志调用。✅（非 finding）
