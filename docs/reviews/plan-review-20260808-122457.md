## Finding 2 [MEDIUM]: Phase F `assert` → guard semantic change

### Evidence

Actual write.py Phase F (lines 370-387):
```python
if bool(str(getattr(args, "routing_challenger_run_approval_input", "") or "").strip()):
    assert challenger_run_plan is not None
    run_approval_exit_code = _verify_and_consume_challenger_run_approval_before_host(...)
```

Plan 11f Phase F (lines 2172-2178):
```python
if challenger_run_plan is not None and bool(
    (args.routing_challenger_run_approval_input or "").strip()):
    run_approval_exit = _verify_and_consume_challenger_run_approval_before_host(...)
```

Two changes:
1. **`assert` removed, replaced with guard**: `assert` crashes on invariant violation (debug signal); guard silently skips. Different failure mode.
2. **`getattr` → direct attribute access**: Plan assumes Protocol structural subtyping makes `args.routing_challenger_run_approval_input` safe. Actual code uses `getattr` for defensive access.

### Impact

- If `challenger_run_plan` is `None` when `routing_challenger_run_approval_input` is set, the assert would crash (loud bug signal); the guard would silently skip the approval verification (silent correctness bug).
- Direct attribute access without `getattr` will raise `AttributeError` if the field isn't set on the argparse namespace (e.g., missing `add_argument` call).

### Recommended Fix

Keep the `assert` and `getattr` pattern from HEAD:
```python
# Phase F: Run Approval Verification（不变）
if bool(str(getattr(args, "routing_challenger_run_approval_input", "") or "").strip()):
    assert challenger_run_plan is not None
    run_approval_exit_code = _verify_and_consume_challenger_run_approval_before_host(
        args=args, paths_config=paths_config, execution_plan=challenger_run_plan)
    if run_approval_exit_code != 0:
        return run_approval_exit_code
```
