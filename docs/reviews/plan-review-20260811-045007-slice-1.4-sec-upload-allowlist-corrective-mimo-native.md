## 2. Corrective Plan 闭合分析

### 2.1 Corrective Plan 措施

plan-fix-20260811-044742 要求在既有 Allowed owner 中补充测试：

- `tests/fins/test_sec_pipeline_upload_filing_stream.py`
- `tests/fins/test_sec_pipeline_upload_material_stream.py`

各自补真实 `SecPipeline.upload_*_stream` overwrite 回归，必须：

1. 使用与 pipeline source/blob owner 同 core 的 recording batching repository
2. 观测真实 source owner 的 `reset_source_document`，而不是 patch workflow helper 为 no-op
3. 对一次 overwrite 断言 `begin_batch` 恰好一次、reset 恰好一次且当时同-core token active、随后恰好一次 commit、零独立前置 AUTO batch/嵌套 batch
4. 在 reset 已发生、commit 尚未开始的真实 service 路径注入失败，断言恰好一次 rollback、零 commit，旧 source meta 与旧 blob bytes 仍可读
5. filing 与 material 两条 workflow 各自覆盖，不以其中一条或 service 单测代替另一条
6. 保留既有 action/status/document id/event order assertions

### 2.2 Finding 闭合验证

**直接证据**：

1. **测试目标明确**: corrective plan 明确要求测试 `SecPipeline.upload_filing_stream` 和 `SecPipeline.upload_material_stream` 的真实调用链，而不是 mock workflow
2. **同-core recording batching**: 要求使用与 pipeline source/blob owner 同 core 的 recording batching repository，确保能观测到真实的 token 传递
3. **观测真实 reset_source_document**: 要求观测真实 source owner 的 `reset_source_document`，而不是 patch 为 no-op，确保测试的是真实行为
4. **断言 begin/reset/commit 顺序**: 要求断言 `begin_batch` 恰好一次、reset 恰好一次且当时同-core token active、随后恰好一次 commit，确保没有前置 AUTO batch
5. **断言 rollback 行为**: 要求在 reset 后、commit 前注入失败时断言恰好一次 rollback、零 commit，旧 source meta 与旧 blob bytes 仍可读
6. **两条 workflow 各自覆盖**: 要求 filing 与 material 两条 workflow 各自覆盖，不以其中一条或 service 单测代替另一条

**结论**：corrective plan 的测试要求能够区分旧 pre-reset 与新 single-owner 行为：

- 如果 SEC/CN workflow 重新加入 `reset_upload_target_for_overwrite`，测试会观测到两次 reset（一次在 workflow，一次在 service），违反"恰好一次 reset"断言
- 如果 workflow 加入前置 AUTO batch，测试会观测到两次 begin（一次在 workflow，一次在 service），违反"恰好一次 begin"断言
- 如果 workflow 加入嵌套 batch，测试会观测到 begin 调用异常或 token 冲突

### 2.3 Service 单测不能替代

plan-fix 明确指出：

- `test_upload_overwrite_batch.py` 继续作为 service-owner 单测
- 但 service 单测不能替代 workflow 级测试，因为：
  - service 单测绕过 workflow，无法检测 workflow 层的行为回归
  - workflow 级测试使用真实 `SecPipeline` 调用链，能检测到 workflow 重新加入 pre-reset

**结论**：service 单测不能替代，需要 workflow 级测试。
