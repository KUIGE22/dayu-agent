## Observations（非 material findings，不阻塞 PASS）

### Obs-1: POSIX-only FD 操作，无 Windows 防护（by design）

- **位置**: `_research_template_bundle.py:641-670, 716-761`
- **说明**: `_open_component_no_follow` 使用 `os.open(..., dir_fd=parent_fd)` 和 `os.stat(..., dir_fd=parent_fd)`，`_open_source_root_no_follow` 使用 `os.open("/", os.O_RDONLY | os.O_DIRECTORY)`。这些 API 均为 POSIX-specific：Windows 上 `dir_fd` 参数抛 `NotImplementedError`，`O_DIRECTORY` 无效，`/` 不存在。
- **风险评估**: 项目运行环境为 macOS (`darwin`)，AGENTS.md 约定 Python 3.11；`init.py:581` 已有 `platform.system() == "Windows"` guard，说明项目已有平台区分意识。当前代码遵循已有 POSIX 约定，非回归。若未来需 Windows 支持，应在 `_open_source_root_no_follow` 入口添加 `sys.platform` 检查并抛出清晰的不支持错误，而非让底层 `NotImplementedError` 泄漏。
- **分类**: 设计选择（项目目标平台为 macOS），非生产缺陷。

### Obs-2: bundle_key 去重缺少专项独立测试

- **位置**: `tests/cli/test_workspace_migrations.py:1281-1458`
- **说明**: `_require_global_identity_uniqueness` 三重去重（security/bundle/locator）逻辑正确，但现有测试只覆盖 security_key 重复（`test_stage_cross_company_duplicate_security_rejected`）和 locator 重复（`test_require_global_identity_uniqueness_rejects_duplicate_locator`）。缺少"两个 company 携带不同 locator 但相同 (exchange_mic, ticker, template_name)"的 bundle_key 专项测试。locator 测试在构造中恰好也会触发 bundle_key 重复，但断言意图是 locator 重复，bundle_key 独立性失去显式保护。
- **风险评估**: 生产代码正确；若未来重构 locator 检查，bundle_key 独立性可能因缺少回归保护而退化。
- **分类**: 测试覆盖观察（defense-in-depth），非生产缺陷。

### Obs-3: cross-company staging 测试无显式 DB connect count = 0 断言

- **位置**: `tests/cli/test_workspace_migrations.py:1281-1458`
- **说明**: 三个 cross-company 测试（行 1281、1339、1411）均只断言异常类型，无显式断言 DB 连接数为 0。这是结构性保证（`stage_workspace_import` 不创建 DB engine/session），不需要行为断言。但若未来有人在 staging 路径中引入 DB 依赖，测试不会 catch。

- **分类**: 测试防御性观察，非生产缺陷。
