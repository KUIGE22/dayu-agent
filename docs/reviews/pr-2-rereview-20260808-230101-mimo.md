## Corrective re-review（SEC 误报闭环复测）

**背景**：首轮 PASS 记录的 SEC-01 实现对「名称符合凭据约定的环境变量值」只做长度（>=16）判断即纳入精确值匹配。DeepSeek 复现出误报路径——若某个 `*_API_KEY` 被设为普通短语或普通长单词，该短语会在任意被扫描文本中被替换为 `<redacted>`，污染诊断输出并可能让 scanner 产生系统性误报。本轮针对该闭环独立复测。

**增量范围核验**：`git diff 783b15a` 显示自首轮以来的生产代码增量**仅** `dayu/redaction.py`（+93/-7 含其后续修订），其余三个生产文件（`async_anthropic_runner.py`、`model_circuit_breaker.py`、`web_search_providers.py`、`model_usage_ledger.py`）与首轮复核内容逐字节一致，故 ANTHROPIC-01 / COVERAGE-01 / DOC-01 的首轮结论不受影响，无需重复复核。

### 实现走读

`dayu/redaction.py:53-85` 新增 `_is_secret_like_environment_value(value)` 作为环境候选**资格门**，`_known_environment_secret_values()`（`:88-111`）改为以该函数替代原先的裸长度判断。三重约束：

1. `:70-71` 长度 `< _MIN_DYNAMIC_SECRET_LENGTH`(16) → 拒绝；
2. `:72-73` 含任意空白字符 → 拒绝（挡住「带空格的普通短语」）；
3. `:74-78` 长度 `>= _MIN_DYNAMIC_HEX_SECRET_LENGTH`(32) 且全部字符属 `_DYNAMIC_HEX_SECRET_CHARACTERS` → 放行（保留纯 hex 形态的真实 key）；
4. `:80-85` 否则要求字母/数字/非字母数字三类中至少命中两类 → 挡住「纯字母普通长词」。

关键设计正确性：hex 放行分支**只作用于环境变量值的资格判断**，不对待扫描文本执行裸十六进制搜索（`:56-58` docstring 明确此边界）。因此未配置的 Git SHA 仍不可能被匹配——它从不进入候选集合。这精确落实了 Controller「不接受裸 `{32,}` 十六进制模式」的范围纠正。
