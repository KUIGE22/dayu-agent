## Findings

### [M] RECORDED health advancement 未与 receipt outcome/error 闭合

- File: `dayu/investment/domain/source_operation.py`
- Lines: 314–327
- Confidence: High
- Evidence: 当前逻辑只用 `health_after.last_source_sync_run_id == receipt.source_sync_run_id` 判定 health 是否推进；推进时仅校验 terminal 时间、snapshot presence 及 snapshot/head identity。它没有校验 receipt outcome 是否允许推进，也没有把 receipt outcome/error 与 head/snapshot status/error 对齐。只读 runtime probes 已确认三条合法构造链都被接受：
  1. canonical `SKIPPED_DISABLED` receipt + 同 run 的 healthy head/provider snapshot；decision 成功构造且 `health_snapshot is not None`；
  2. canonical `FAILED/provider_unavailable` receipt + 同 run 的 healthy head/snapshot；decision 成功构造；
  3. canonical `NO_CHANGE` receipt + 同 run 的 degraded/provider_unavailable head/snapshot/alert；decision 成功构造。
  现有 `test_recorded_terminal_decision_snapshot_presence_tracks_health_advance_exactly` 只证明 presence，不覆盖 receipt outcome/status/error matrix。
- Impact: §7.1 明确 `SKIPPED_DISABLED` 不改变 head、不写 snapshot/alert；success/no-change 必须推进为 healthy，partial/failed 必须推进失败状态并携带对应 error。当前 public decision boundary 可接受互相矛盾的 durable receipt、health head、snapshot 乃至 alert，因而 repository 的组装/重读错误不会 fail closed，可能持久化“run 失败但 health healthy”或“no-change 却 degraded 并告警”的证据链。
- Fix: 在 `health_advanced` 分支增加 closed outcome-to-health validation：拒绝 `SKIPPED_DISABLED`（`STALE_SUBSCRIPTION` 已由 action 分支处理）；`SUCCEEDED/NO_CHANGE` 要求 healthy/0/None；`PARTIAL/FAILED` 要求非 healthy、failures > 0 且 `health_after.safe_error_code is receipt.safe_error_code`。保留任意 provider outcome 在并发 disabled 时走 no-op 的能力。为全部 outcome 添加参数化 direct tests，至少固定上述三条反例及 provider late-disabled no-op。

### [L] Package-root guard 忽略增量修改 `__all__` 的 re-export

- File: `tests/investment/test_architecture_boundaries.py`
- Lines: 2685–2760
- Confidence: High
- Evidence: `_package_root_reexported_source_symbols` 只处理 `ast.Assign` / `ast.AnnAssign`，完全忽略 `ast.AugAssign`。对以下 synthetic package root：`__all__ = []`，随后 `from .source_health import SourceHealthStatus as _SourceHealthStatus`，再执行 `__all__ += ['_SourceHealthStatus']`，helper 实际返回 `frozenset()`；因此 line 3290 的 package-root assertion 会通过，但 Python 的 star import 会按 runtime `__all__` 转发该 owner symbol。新增 collector test 只覆盖单次 literal `__all__ = [...]`，没有覆盖该语法。
- Impact: §3.2/§3.2 responsibility ratchet 要求两个 package root 不 compat re-export 且结构测试 fail closed。后续一次无意或刻意的 `__all__ +=` 可绕过门禁，重新引入 indirect import path 与 owner coupling；当前 production root 尚未出现该模式，所以风险为 architecture regression 而非已发生运行时故障。
- Fix: 对 package-root `__all__` 采用 fail-closed policy：要么只允许唯一一次 literal list/tuple assignment并拒绝任何 `AugAssign`、`.append/.extend` 或动态构造，要么完整解析这些 mutation 并追踪 private alias provenance。加入本 finding 的 synthetic negative fixture，并保留现有 relative/direct assignment/literal `__all__` fixtures。
