## H1: downgrade admission linearization

- `_downgrade_admission()` calls `_lock_downgrade_targets()` before any
  catalog, business-data, conflict, or dependency read.
- The lock helper makes one deterministic request covering exactly
  `source_health_alert_outbox`, `source_health_states`,
  `source_sync_operations`, `source_health_snapshots`, `source_sync_runs`,
  `source_subscriptions`, and `job_attempts`:
  `LOCK TABLE ... IN ACCESS EXCLUSIVE MODE NOWAIT`.
- `NOWAIT` is an intentional stronger quiescence admission than waiting for a
  dirty writer. No blocking lock order can be compatible with both repository
  parent-first row locking and direct-DML child-first/FK locking. Immediate
  `55P03` rollback prevents the migration from joining either wait graph. Only
  when every lock is obtained does the transaction reach its linearization
  point; the locks remain held through destructive DDL and revision update.
- The helper also fails closed unless the migration transaction reports
  `transaction_isolation = read committed`, preventing an older
  REPEATABLE READ/SERIALIZABLE snapshot from invalidating post-lock admission
  reads.
- The PG owner uses two real connections without sleep or a worker thread. An
  uncommitted app operation holds `RowExclusiveLock`; the second Alembic
  connection must receive typed `psycopg.errors.LockNotAvailable`. A test-only
  database `statement_timeout` bounds a regression where `NOWAIT` is removed
  without producing the same lock error. After writer commit, a second
  downgrade sees the dirty row and rolls back, preserving revision, row, and
  added column. A REPEATABLE READ database-default negative case separately
  proves the isolation gate and zero destructive mutation.
