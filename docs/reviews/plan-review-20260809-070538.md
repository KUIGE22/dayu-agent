## 三、新增 finding

### PRR-001-已修复-[中]-模板指纹只覆盖 `common.md`/`technology.md`，遗漏 materialization 实际读取的 `定性分析模板.md` 与 `technology.definition.json`

- **位置**：plan 第 5.1 节第 112-113 行（「common/technology 模板指纹必须来自 `resolve_package_assets_path()/research_templates/{common,technology}.md`」、receipt 绑定项「package technology/common 模板 SHA-256」）、第 4.2 节第 102 行、第 9 节 Slice 1 第 307 行「指纹测试证明 …… common/technology 来自 `resolve_package_assets_path()`」、第 12/13 节漂移判定（第 328、584 行）
- **问题类型**：契约缺失 / 指纹覆盖不足
- **当前写法**：plan 把 package asset 模板指纹的真源精确限定为两个文件：`research_templates/common.md` 与 `research_templates/technology.md`，并把「package templates 漂移」列为 subprocess 前失败与 stop condition 的判据。
- **反例/失败场景**：13 个 materialization 产物并不只由这两个文件决定。
  1. 首个产物 `common-plus-technology.md` 由 `build_composed_research_template_text()` 生成（`dayu/cli/research_template_assets.py:59-80`），除 `common.md` + `technology.md` 外，还**必须**读取 `resolve_package_assets_path() / "定性分析模板.md"` 作为 base write 模板（`:69-72`，缺失即 `FileNotFoundError`），并按其 `## 来源清单` 位置插入研究章节。该文件实存于 `dayu/assets/定性分析模板.md`，但不在 plan 的指纹集合内。
  2. `technology.checklist.md` 与 bundle 的 checklist 完整性校验由 `load_research_template_definition()` 读取 `technology.definition.json` 驱动（`dayu/cli/commands/_research_template_core.py:178`、`dayu/cli/research_template_definitions.py:27/115-117`、`_research_template_bundle.py:203-210`），与 `technology.md` 是两个独立资产文件（`dayu/assets/research_templates/` 下 `technology.definition.json` 与 `technology.md` 并存）。

  因此若 `定性分析模板.md` 或 `technology.definition.json` 在两次 run 之间发生变化，13 个产物的实际内容会改变，但 plan 定义的 template fingerprint 完全不变、漂移检测不触发、stop condition 不触发。此时「相同 live artifacts 的 `verify` 必须得到相同 normalized score/receipt」（第 251 行）与「配置/模板漂移即换 run」（第 8.2 节语义）都不再由指纹保证。
- **为什么有问题**：plan 把模板指纹提升为 hard stop condition 与可复现性真源（第 209 行「可复现与恢复」10 分项、第 328/584 行漂移即失败）。一个覆盖不全的指纹比没有指纹更危险：它给出「资产已锁定」的错误保证，使 PR-004 修复所建立的「一切外部输入均指纹化」不变式出现缺口。该缺口不会在 Slices 0–4 暴露（fixture 固定），只会在跨 revision 复跑或有人改动 `dayu/assets/` 时静默产生不可解释的产物差异。
- **直接证据**：
  - `dayu/cli/research_template_assets.py:59-80`（composed 模板必须读取 `定性分析模板.md`，缺失即抛错）
  - `dayu/assets/` 目录实际内容：`research_templates/`、`定性分析模板.md`
  - `dayu/cli/research_template_definitions.py:27`（`_DEFINITION_SUFFIX = ".definition.json"`）、`:115-117`
  - `dayu/cli/commands/_research_template_core.py:178-186`（checklist 由 definition 渲染）
  - `dayu/cli/commands/_research_template_bundle.py:203-210`（bundle 用 definition 重算 checklist 做完整性校验）
  - `dayu/assets/research_templates/` 同时存在 `technology.md` 与 `technology.definition.json`
  - plan 第 112-113、307、328、584 行
- **影响**：模板漂移不可检出 / receipt 可复现性声明弱于其字面承诺 / 跨 run 产物差异无法归因 / 第 6 节「可复现与恢复」评分项失去支撑证据
- **建议改法和验证点**：
  1. 把第 5.1 节模板指纹真源从「两个 `.md`」改为「`resolve_package_assets_path()` 下参与本次 materialization 的全部资产 canonical tree 指纹」，至少显式列出 `research_templates/common.md`、`research_templates/technology.md`、`research_templates/common.definition.json`、`research_templates/technology.definition.json` 与 `定性分析模板.md`；
  2. receipt 绑定项与第 12/13 节漂移判据同步改为该扩展集合；
  3. 验证点：Slice 1 的指纹测试断言指纹集合包含上述文件，并增加「仅改动 `定性分析模板.md` 或 `technology.definition.json` → 指纹变化 → subprocess 前 fail」的用例，与已有「仅改动 `technology.md` → fail」用例对称。
- **修复风险（低）**：仅扩大 plan 中已有的指纹集合定义与对应 slice 断言，不改生产代码，不改架构边界。
- **严重程度（中）**
