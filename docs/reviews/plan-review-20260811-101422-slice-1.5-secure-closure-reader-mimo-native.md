## 3. Adversarial Validation

### 3.1 Mixed/duplicate CLI parameters

S15-CTRL-04 已要求：import 语义参数（`--import-manifest` / `--target-tenant-id`）
在无主开关时、任一缺失时、任一重复时均先于 `Path.resolve()` / 目录创建 / workspace
lock / 任何普通 init 副作用返回 `workspace_import_usage`。三项 import 参数只能与
`--import-existing-workspace` 一起出现；两项重复时由 `_ImportSemanticStore` 记录
`seen/repeated` 并由同一 gate 拒绝。Terra 1 已修复，plan 已冻结该行为。
**结论：无 open finding。**

### 3.2 Cross-company security/bundle deduplication

S15-CTRL-05 要求 staging 在 DB connect 前对全部 company 建立全局 canonical
security identity（`exchange_mic+ticker`）与 bundle identity 集合；跨 company
重复直接抛 staging 错误。Terra 3 已修复，plan 已冻结该行为。
**结论：无 open finding。**

### 3.3 Descriptor changes during snapshot creation

S15-CTRL-15 §2 要求：任一 component/leaf 变化、缺失、重复、非 regular 或不在
snapshot 时 fail closed。所有 FD 必须在 success/exception/cancel 路径关闭。snapshot
是 immutable bytes，创建后不再访问 source tree。若 snapshot 创建期间有并发修改，
FD-based 读取捕获的是 FD 打开时刻的 bytes，hash 从 FD 计算，snapshot 与实际读取
一致；后续 validator 只消费 snapshot，不重读 source tree。
**结论：无 open finding。**

### 3.4 Reference path alias/relative/absolute/case

S15-CTRL-15 §2 要求所有 closure member 必须从 source-root FD 逐段以
`O_DIRECTORY|O_NOFOLLOW` 打开中间组件、以 `O_RDONLY|O_NOFOLLOW` 打开末端并
`fstat` regular。路径在 lstat 后经 resolve + contained 于 source root。snapshot
key 使用 original canonical contained path。任何 alias/relative/absolute/case
变体在 FD 打开阶段即被拒绝（路径不在 source root 内时无法从 source-root FD 到达）。
**结论：无 open finding。**

### 3.5 Missing reader key

S15-CTRL-15 §3 要求：传 reader 时，source-tree 的读取只能来自 reader snapshot。
S15-CTRL-15 §5 要求：unknown snapshot path fail closed。若某 closure member 未被
snapshot 包含，validator 调用 `content_reader.is_regular_file()` 返回 `False`、
`content_reader.read_bytes()` 抛错 → 相应分支 fail closed。
**结论：无 open finding。**

### 3.6 source_write_manifest 选择语义 / company facets

S15-CTRL-15 §3 明确列出生效范围：`source_write_manifest` 的
`_build_write_manifest_binding_semantics` / `_resolve_template_selection_from_write_manifest`
/ `_load_company_facets_from_manifest`，以及 `validate_research_template_bundle_descriptor`
调用链中的 company facets、template selection semantics。传 reader 时，这些调用只能
命中 snapshot；`_load_json_object` / `read_text` 改走 `content_reader.read_bytes()` 后
自行 `json.loads` / 解码。Package assets（如 `_resolve_template_path`）仍走原 owner。
**结论：无 open finding。**

### 3.7 workbook / report / checklist / monitoring 透传分支

S15-CTRL-15 §3 要求：`validate_research_template_bundle_descriptor` 及其
monitoring/checklist/workbook/report 调用链只增加 keyword-only optional
`content_reader=None` 透传。S15-CTRL-15 §5 要求 per-branch adversarial tests：
每种 re-read 分支在 snapshot 建成后把路径替换为外部 symlink，external bytes 的
ordinary `Path` read/open/hash=0。
**结论：无 open finding。**

### 3.8 None 行为回归

S15-CTRL-15 §3 要求：`None` 时必须走原路径与原错误/返回语义。S15-CTRL-15 §4
要求：默认 reader 的 executable AST（去 docstring）及所有既有 owner tests 必须
证明无行为漂移。实现 artifact 声称 888 测试通过，`test_research_template_command.py`
既有 corpus 无回归。
**结论：无 open finding。**

### 3.9 FD close/cancel

S15-CTRL-15 §2 要求：所有 FD 必须在 success/exception/cancel 路径关闭；不落盘
临时正文。S15-CTRL-15 §5 要求：FD 打开/关闭计数 exact；Linux/macOS
no-follow flags/dir_fd 结构受测试约束。
**结论：无 open finding。**

### 3.10 Tests 是否只是 spy 实现而未证明外部 bytes 未读

S15-CTRL-15 §5 adversarial tests 要求 per-branch：snapshot 后替换路径为外部
symlink，断言 "external bytes 的 ordinary `Path` read/open/hash=0"。这意味着
测试需要对真实 filesystem 读取函数（`path.open`、`read_text`、`_load_json_object`、
`_sha256_file`）做 spy/mock 并断言调用次数为 0，而不仅仅是对内部函数做 spy。
这足以证明 snapshot 隔离了外部 bytes 读取。
**结论：无 open finding。**（plan 要求的断言语义正确；实现侧需确保 spy 目标是
真实的 filesystem 读取入口而非仅内部函数。）

### 3.11 Neutral leaf 与 owner 边界 / 过度设计 / 跨平台

- 不使用 `/dev/fd`、特殊 `Path`、global monkeypatch → 不依赖平台特定 hack。

  正确性有保障。
**结论：无 open finding。**
