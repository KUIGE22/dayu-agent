## Findings

### 1-未修复-[中]-非法 `JobFailure` 可绕过 handler `CANCELLED` 门禁并使 Worker 退出

- **入口/函数**: `JobService.execute_claim` 接收 handler 返回值，随后由 `PlatformWorker._finalize_handler_result` 持久化 failure。
- **文件(行号)**: `dayu/investment/domain/jobs.py:1342-1374`；`dayu/services/job_service.py:784-789`；下游证据为 `dayu/host/worker.py:1005-1007,1144-1193,660-690` 与 `dayu/investment/storage/postgres_jobs.py:1547-1574,1622-1646,1725-1730`。
- **输入场景**: 动态、第三方或违反静态类型的 handler 返回 `JobFailure(safe_error_code="cancelled", retryable=False)`；同样的问题适用于其它 raw string、`None` 或非枚举对象。`@runtime_checkable` 只检查属性存在，当前测试也明确证明它不验证 callability、arity 或返回字段运行时类型。
- **实际分支**: `JobFailure.__post_init__` 只验证 `retryable` 的布尔类型和部分枚举组合，没有先验证 `safe_error_code` 是 `SafeJobErrorCode`。因此 raw string `"cancelled"` 可构造成功；`execute_claim` 又使用 `result.safe_error_code is SafeJobErrorCode.CANCELLED`，该 raw string 绕过 identity gate并被作为合法 `JobFailure` 返回。
- **预期行为**: accepted plan §3.1 要求任何 handler 自报 generic `CANCELLED`，以及 handler 的非法返回，稳定收窄为 non-retryable `HANDLER_REJECTED`；只有 PostgreSQL cancel-intent 路径能生成 generic `CANCELLED` receipt。
- **实际行为**: Worker 的顶层 `isinstance(JobFailure)` 检查同样无法识别内部字段畸形，于是将 malformed failure 交给 `gateway.fail`。`PostgresJobStore.fail` 构造 generic receipt 时把 raw code传给 `build_generic_attempt_receipt`；closed matrix/后续 `.value` 消费抛出异常，事务回滚并重新抛出。该未分类异常由 Worker `run()` 收窄为 exit code `1`，attempt/lease留待 recovery，而不是持久化稳定 `HANDLER_REJECTED`。
- **直接证据**:
  - `jobs.py:1358-1374` 无 `isinstance(self.safe_error_code, SafeJobErrorCode)`；同模块 `AgentRunGovernanceResult.__post_init__` 在 `1966-1967` 已采用这种闭合类型检查，证明项目有明确先例。
  - 独立运行时对抗复现：`JobFailure("cancelled", False)`、`JobFailure("source_invalid", False)`、`JobFailure("bogus", False/True)`、`JobFailure(None, False)` 当前均构造成功；只有碰巧与某枚举成员相等且进入 retryability tuple 的反向组合会被拒绝。
  - `job_service.py:786-789` 对任一 `JobFailure` 除 enum identity `CANCELLED` 外都原样返回，未验证字段。
  - `worker.py:1177-1182` 将结果交给 failure gateway；`postgres_jobs.py:1639-1645` 用其 code构造 receipt，`1728-1730` 对异常 rollback 后重新抛出；`worker.py:681-682` 将其转为 runtime exit `1`。
- **影响**: 不会伪造 persisted `CANCELLED`，但单个 malformed handler 返回可升级为整个 Worker runtime failure、未收敛 lease 与后续 recovery churn；同时破坏“handler 非法返回统一为 `HANDLER_REJECTED`”的稳定 gateway contract。Item 7 引入第一个 production handler 后，该动态信任边界会进入生产主链路。
- **建议改法和验证点**:
  1. 在 `JobFailure.__post_init__` 的组合判断前精确要求 `isinstance(self.safe_error_code, SafeJobErrorCode)`，非法类型抛 `JobInputError`；同步修正文档异常说明。
  2. 在 `JobService.execute_claim` 对 handler 返回的 `JobFailure` 做防御性 closed-field 校验；即使恶意/动态 handler 绕过构造器（例如 `object.__new__`），也必须映射 `_handler_rejected_failure()`，不得进入 Worker/Store。
  3. 增加 raw `"cancelled"`、其它 raw code、`None` 与构造器绕过对象的对抗测试，证明 gateway 返回 `HANDLER_REJECTED`、不调用 `gateway.fail` 的下游状态机；保留正常枚举 source error/retry矩阵。
- **修复风险（低/中/高）**: 低。
- **严重程度（低/中/高/严重）**: 中。
