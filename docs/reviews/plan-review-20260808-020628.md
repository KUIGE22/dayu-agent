## 2. 双 Owner 语义精确性验证

### 2.1 Plan 声明

Plan §1.8:355-367:

> - `dayu.cli.commands.write._challenger_requested` 是 `run_write_command` 内 3 个 global call site 的正确 monkeypatch owner
> - `dayu.cli.commands._write_params_validation._challenger_requested` 是真实 `_validate_research_materialization_args` 函数内部调用的正确 monkeypatch owner
> - 禁止把所有旧 `write._challenger_requested` patch blanket 迁到 params
> - monkeypatch 必须按被测 call site 的函数 globals 选择 owner

### 2.2 源码验证

**`run_write_command` 的 globals**（定义在 `write.py:4602`）: `__globals__ == write.__dict__`。迁移后 `write.__dict__["_challenger_requested"]` 来自 `from _write_params_validation import _challenger_requested`。
- monkeypatch `write._challenger_requested` → 替换 `write.__dict__["_challenger_requested"]`
- `run_write_command` call-time global lookup → 命中 patched binding ✓

**`_validate_research_materialization_args` 的 globals**（迁移后在 `_write_params_validation.py` 定义）: `__globals__ == _write_params_validation.__dict__`。内部调用 `_challenger_requested(args)` 解析为 `_write_params_validation.__dict__["_challenger_requested"]`。
- monkeypatch `_write_params_validation._challenger_requested` → 控制 validator 内部路径
- monkeypatch `write._challenger_requested` → **不**影响 validator 内部路径 ✓

**语义精确性结论**: 两个 owner 按被测 call site 的函数 globals 精确区分，无歧义，无遗漏。✓

## 3. Line 5934 保留理由验证

### 3.1 Plan 声明

Plan §5 Slice 5:880-882:

> 现有 engine test 约 line 5934 同时 patch validator 本身与 `write._challenger_requested`，用于 `run_write_command` 路径，保持不变。

### 3.2 源码验证

`tests/engine/test_cli_running_config.py:5932-5934`:
```python
monkeypatch.setattr(
    write_command_module,
    "_challenger_requested",
    lambda _args: True,
)
```

- `write_command_module` 是 `dayu.cli.commands.write` 模块引用（line 21: `from dayu.cli.commands import write as write_command_module`）
- 此测试 patch `write._challenger_requested` = True，服务于 `run_write_command` 路径（让 Challenger 分支被激活）
- 迁移后 `write._challenger_requested` 仍存在于 `write.__dict__`（via functional import from `_write_params_validation`），patch 行为等价

**保留理由验证**: 此 patch 的目标是控制 `run_write_command` 内的 `_challenger_requested(args)` 返回值（行 4829/5079/5191）。`run_write_command` 的 globals 是 `write.__dict__`，所以必须 patch `write._challenger_requested`，不能迁到 `_write_params_validation._challenger_requested`。理由充分。✓
