## Findings

### F-01 [Low] `DayuCliArguments` 字段声明与运行时实际字段集不一致

**位置**: `dayu/cli/arguments.py:19-22`

**描述**: `DayuCliArguments` 仅声明 `research_template_action: str` 一个字段，但 39 个 runner 通过 `getattr` 访问的运行时字段至少包括：`json`, `name`, `output`, `base`, `overwrite`, `write`, `limit`, `ticker`, `company`, `recursive`, `workbook`, `backup`, `bundle`, `rules`, `source_map`, `approval`, `manifest`, `plan`, `portfolio`, `report`, `source_map`, `item_id`, `status`, `response`, `analyst_notes`, `evidence_file`, `timezone`（约 27 个不同字段名）。

**为什么不是 High**: 这些字段由 argparse 动态填充，运行时正确存在。pyright 对 `argparse.Namespace` 子类的动态属性访问不做报错（`from __future__ import annotations` 延迟求值 + Namespace 允许任意属性）。功能正确，897 测试通过。

**为什么是 Low**: 从类型安全角度看，`DayuCliArguments` 的声明与实际字段集之间存在语义差距。但这是 argparse 的固有限制——要在运行时类型身份（`isinstance` checks）与完整字段声明之间做取舍。当前选择是合理的：Slice 11 将按计划原子追加 Write Protocol 的 20 个字段。

**风险**: 无功能性风险。如果未来 runner 访问一个不存在的字段且 argparse 也未填充，`getattr` 的默认值会静默返回，可能掩盖配置错误。但当前所有字段均由 argparse 子 parser 注册，不会发生。

### F-02 [Low] `_resolve_research_template_action` 对已声明字段使用 `getattr` 防御性访问

**位置**: `dayu/cli/commands/research_template.py:114`

**描述**: `args` 参数类型为 `ResearchTemplateDispatchArguments`（Protocol，声明 `research_template_action: str`），理论上可以直接 `args.research_template_action`。但实现使用 `str(getattr(args, "research_template_action", "") or "").strip().lower()`。

**为什么不是违反**: AGENTS.md 约束"使用 `hasattr`/`getattr` 必须有充分理由，不能把它当作逃避类型与边界设计的手段"。此处有充分理由：
1. 保留 HEAD 的防御性语义——处理 `None`、非字符串、缺字段的边界情况。
2. `DayuCliArguments` 继承 `argparse.Namespace`，字段可能未被 argparse 填充（如测试中直接构造实例）。
3. 测试 `test_selector_preserves_defensive_normalization` 明确覆盖了 `None`、缺字段、非字符串场景。

**结论**: 有充分理由，不构成违反。

### F-03 [Low] `research_template.py` 文件体积从 834 行增长到 1369 行（+64%）

**位置**: `dayu/cli/commands/research_template.py`

**描述**: 增长主要来自为 39 个 runner 补齐中文 docstring（每个约 12 行），以及新增 `_resolve_research_template_action` + mapping 常量。函数体逻辑未变。

**为什么不是 High**: 增长是 docstring 驱动的，符合 AGENTS.md"函数必须提供完整中文 docstring"的硬约束。无 God function 产生。

**为什么是 Low**: 文件仍为单模块、单一职责（research-template dispatch），39 个 runner 各自独立、无嵌套。符合"优先使用模块级私有辅助函数"的约束。

### F-04 [Info] `ResearchTemplateDispatchArguments` Protocol 仅被一处使用

**位置**: `dayu/cli/arguments.py:13-16`, `dayu/cli/commands/research_template.py:100`

**描述**: Protocol 仅用于 `_resolve_research_template_action` 的参数类型注解。`run_research_template_command` 及全部 39 个 runner 直接使用 `DayuCliArguments`。

**评估**: 这是正确的设计——Protocol 定义 selector 的最小消费契约，不强制 runner 也受此约束。如果未来有其他模块需要以不同实现调用 selector，Protocol 已就位。当前单处使用不构成过度设计。
