## Finding

### PR-B01-未修复-中-EvidenceLink 两个 target 分支的剩余列可绕过闭合

- **位置**：V8 §3.2 L50、§4 L64–65、§7 L117；主计划 Slice 3.1 要求 same-tenant/company private endpoint 和 cross-company link reject。
- **问题类型**：schema/storage 契约缺失；原始 SQL 闭合与 nullable 复合 FK 边界。
- **当前写法**：V8 L65 给 Fact arm 的 DB CHECK 仅列出 `(fact_id 非空, locator_json NULL, digest NULL)`，没有限制 direct-only `security_id` 与 `locator_ticker`。direct arm 列出 `(fact_id NULL, security_id 非空, locator_json 非空, digest 32 bytes)`，没有明确 `locator_ticker IS NOT NULL` 及与 `locator_json->>'ticker'` 在 DB 层相等。L64 又依赖 `(company_id,security_id,locator_ticker)` 复合 FK 实现公司/证券/ticker 闭合。
- **反例**：若照明列出的 CHECK 实施，持合法 ClaimVersion/Fact 的 raw INSERT 可令 Fact target 带另一个 security ID，或令 direct target 的 `locator_ticker=NULL`、JSONB ticker 有效、security_id 指向其他公司。前者被描述为 Fact target，却携带不受该 Fact 约束的 direct-only 身份；后者的复合 FK 因一个引用列为 NULL 而免于查找，未证明公司/证券闭合。此反例不要求伪造 digest：BEFORE INSERT trigger 会自行填入 32-byte 值。
- **为什么有问题**：PostgreSQL 16 默认 `MATCH SIMPLE` 的多列 FK 在任一引用列为 NULL 时不要求匹配，除非用非空约束或 `MATCH FULL`/适当 CHECK 闭合。V8 声称 DB 层三重拒绝和 raw SQL 畸形组合拒绝；当前列出的 CHECK 留下空值绕过路径。官方依据：[PostgreSQL 16 CREATE TABLE foreign-key match semantics](https://www.postgresql.org/docs/16/sql-createtable.html)。
- **直接证据**：V8 L50 的 Fact 或 `(security_id,完整 locator)` 二选一目标身份；L64 的三列复合 FK；L65 的两个 CHECK arm 精确文本；L117 只要求“非法组合 CHECK 拒绝”而没有覆盖上述混合列/NULL 反例。主计划 L4298–4307 明定 private endpoints 同 tenant 且跨公司 link reject。
- **影响**：实施 Agent 可忠实实现文本却让 raw SQL 留下歧义 Fact link 或跨公司 direct link；后续读取、冲突身份比较和研究证据归属可能不一致，PG 用例若只测试非空 locator 将漏掉。
- **建议改法与验证点**：把 EvidenceLink DB CHECK 的两臂写成完整列形状。若 Fact arm 不使用 direct 元数据，明确 `security_id IS NULL AND locator_ticker IS NULL`；若确需冗余证券信息，则要求以 Fact 同行身份作可执行的约束，不能任意值。direct arm 明确 `security_id IS NOT NULL AND locator_ticker IS NOT NULL`，且 DB 约束或 STORED generated column 保证它等于已校验 JSONB 的 ticker；再由复合 FK 闭合公司/证券。真 PG 用 app-role raw INSERT 测 Fact+残余 security、direct+NULL ticker、direct 错 ticker/错公司均拒绝，正常双证券同 locator 保持成功。不要在 repository parser 中替代 DB 测试。
- **修复风险**：低，仅明确新 0007 的 CHECK/列和测试；尚无迁移数据。**严重程度**：中。**状态**：accepted-candidate，待 Controller 裁决。
