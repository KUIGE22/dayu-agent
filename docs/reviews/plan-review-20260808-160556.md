## 1. Adversarial 命题裁决

### 命题 A: `5821014` ratchet 是否避免 tautology 且不掩盖 PR-level origin/main +216

**裁决: ACCEPTED — 两层分离正确**

**Tautology 检验**:
- Controller 明确拒绝 "用 current HEAD 建 baseline"（比较自身 = tautology）
- `5821014` 的 BASE total=364 > HEAD total=335，positive=`{}`，negative=29
- 这是非退化的实质性证据：architecture refactor 实际**减少**了 29 个 lint findings
- 如果是 tautology，BASE 和 HEAD 的 multiset 会完全相同

**+216 掩盖检验**:
- Architecture gate（`5821014` baseline）和 PR residual（`origin/main` baseline）是两个独立的、显式分离的比较
- AGG-RUFF-CTRL-03 明确声明："origin/main positive 216 作为 PR-level residual 强制输入 aggregate deepreview，但不阻断 architecture gate"
- +216 的 per-rule breakdown（B009:53, TRY004:118, FURB162:12, RUF010:22, etc.）在 erratum §2.3 中逐项列出
- 两层 baseline 各有明确用途：architecture gate = refactor 非退化；origin/main = PR 全量 residual

**潜在弱点（非阻断）**: `5821014` 已含 `research_template.py`（10 文件），说明该文件在 architecture refactor 开始前已存在。这意味着 ratchet 比较的是"refactor 前后"而非"有/无 research_template"。但 BASE=364 > HEAD=335 证明 refactor 确实改善了 lint 状态，比较仍有意义。

### 命题 B: Ruff 0.16.1 与 constraints 0.15.11 区分是否足够

**裁决: ACCEPTED WITH RESERVATION — 区分已记录，但版本漂移风险未闭合**

**已做到的区分**:
- erratum 明确写："constraints/min-py311.txt 固定 Ruff 0.15.11，其 CI/default E/F 语义也不能替换上述 architecture gate"
- AGG-RUFF-CTRL-02 锁定 "Ruff 0.16.1、无显式 rule select"
- `uv run --no-project --with ruff==0.16.1` 确保版本固定、可复现

**未闭合的风险**:
- Ruff 0.15.11 vs 0.16.1 的 rule set 差异**未量化**。两者 "无显式 select" 的 default rule set 可能不完全相同（0.16 可能新增/修改了规则）
- 如果未来 CI 升级 Ruff 到 0.16.1+，architecture gate 和 CI 的规则集会趋同，但当前版本差是真实存在的
- erratum 没有给出两个版本的 rule set diff 或说明为何选择 0.16.1 而非 0.15.11

**建议**: 在 plan 中注明选择 0.16.1 的理由（如：Slice-report artifact 使用的版本），并记录 0.15.11→0.16.1 的 rule set 差异（如有）。当前不阻断，但应作为 L 级 open issue。

### 命题 D: 不修 TRY004/B009、不加 Slice 14 是否合理

**裁决: ACCEPTED — 三项拒绝理由均成立**

**TRY004（118 findings）**:
- `isinstance(x, ValueError)` → 建议改为 `TypeError`
- erratum 理由："改变异常类型是行为变更，except 子句匹配行为不同"
- **adversarial 检验**: 这是正确的。`raise ValueError("bad arg")` 和 `raise TypeError("bad arg")` 在 `except ValueError` 处理器中的行为截然不同。118 处机械替换有非零回归风险。
- **额外证据**: 154611 的 §4.1 详细分析了 TRY004 的 call-chain 风险

**B009（53 findings）**:
- `getattr(args, "field_name", default)` → 建议改为 `args.field_name`
- erratum 理由："argparse dispatch 的设计模式，plan S10-CTRL-04 已记录理由"
- **adversarial 检验**: `getattr` 在 argparse Namespace 上是防御性访问（字段可能不存在）。直接属性访问在字段缺失时抛 `AttributeError`，行为不同。
- **额外证据**: origin/main 有 3 个 B009 finding，说明这是既有模式，非本分支引入

**FURB162（12 findings）**:
- `astimezone(UTC).replace(tzinfo=None)` → 建议简化
- erratum 理由："改变时区语义"
- **adversarial 检验**: `replace(tzinfo=None)` 将 aware datetime 转为 naive datetime，语义上是有意的。移除会改变后续 datetime 比较行为。

**Slice 14**:
- AGG-CTRL-03 已明确 "不新增 Slice 14"
- 216 findings 中 ~188 来自新功能代码（origin/main 不存在），~18 来自文件拆分计数漂移
- 修复这些 findings 不属于 architecture refactor scope
- **adversarial 检验**: 如果把 216 修复推入 Slice 14，该 slice 的实质是 "lint cleanup"，不是 "architecture refactor"。这违反了 work unit 的 scope 定义。

### 命题 E: CI 无 production Ruff 是否如实 residual

**裁决: ACCEPTED — 事实准确，处置正确**

- CI PR Required workflow: pyright + pytest only，**无 ruff check**
- Dual Model Gates: ruff check 仅覆盖 9 个 utils/ + tests/ 文件

- **adversarial 检验**: 正确识别了 CI 的 coverage gap，且正确选择不在本 work unit 中修改 workflow（scope 越界）
