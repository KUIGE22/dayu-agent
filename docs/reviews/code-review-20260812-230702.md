- **预期行为**: §3.2 的五 owner exact `__all__` ratchet 与本轮冻结目标要求 literal `__all__` 只能有一次 assignment，任何 `+=`、`.append/.extend`、动态构造或把 `__all__` 传给 mutation helper 都必须 fail closed。

- **建议改法和验证点**: 统一 owner/root 的 `__all__` 解析策略，让 `_top_level_defined_symbols` 也调用同一 literal-only validator；更稳妥的是对这七个模块的 top-level AST 建立允许语句白名单，拒绝所有额外 `__all__` reference、间接 `globals/vars` write 与动态 mutation。给 owner collector 加 `+=`、append、extend、helper-pass negative fixtures，并给 root collector增加间接全局 mutation fixture。
