## Findings

### 未发现实质性问题

逐一沿必查清单走读：

#### 1. github.sha checkout
- CI 使用 `pull_request` 事件，`github.sha` 为 merge commit
- `_verify_and_resolve_head(head)` 比较 `git rev-parse HEAD`（实际 checkout）与 `git rev-parse --verify head`（参数），不一致时 fail-closed exit 2
- **证据**: `ci_pr_pyright.py:177-202`，`ci-pr-required.yml:32-33`

#### 2. base SHA depth=1 fetch
- `_ensure_ref_available(base)` 先 `git cat-file -e ref`，不存在时 `git fetch --no-tags --depth=1 origin ref`
- 对 `pull_request` 事件 + `fetch-depth: 1` 的标准 checkout，base SHA 通常不可见，自动 fetch 补全
- `--depth=1` 只拉取单个 commit 对象（tree + parent stub），足以支撑 `git diff base head`
- **证据**: `ci_pr_pyright.py:154-174`

#### 3. 浅克隆无 merge-base
- `_parse_changed_entries` 使用双点 `git diff --name-status --diff-filter=ACMRTD base head`（直接比较），不依赖 merge-base
- 测试 `test_shallow_clone_direct_comparison` 真实构造 `file://` bare origin + `--depth=1` clone + fetch base SHA，断言 `git merge-base` 失败而双树 diff 成功
- **证据**: `ci_pr_pyright.py:231-249`，`test_ci_pr_pyright.py:422-482`

#### 4. 双树 diff 与 rename/copy/delete/no-Python
- `--diff-filter=ACMRTD` 覆盖 Add/Copy/Modify/Rename/Type-change/Delete
- R 状态需三列（old→new），C 状态用 parts[2] 作新文件，D 状态归入 deleted_files
- 非 `.py` 文件通过 `new_path.suffix != ".py"` 过滤
- malformed 行 fail-closed exit 2（测试覆盖 C/R/普通行缺列、未知 status letter）
- **证据**: `ci_pr_pyright.py:246-309`，`test_ci_pr_pyright.py:373-416`

#### 5. unchanged consumer 新增诊断
- `_classify_head_diagnostics` 中 `all_changed` 仅含 `.py` 变更文件
- 未变更文件走 identity 行映射 + Counter 消耗；Counter 中无匹配则判为新增
- 测试 `test_unchanged_file_new_diagnostic_fails` 和 `test_no_py_changes_still_runs_full_compare` 覆盖
- **证据**: `ci_pr_pyright.py:743-749`，`test_ci_pr_pyright.py:884-939`

#### 6. Counter 多重集

## Residual Risk

1. **CI 行为变更**：`ci-pr-required.yml` 从"零 pyright 错误"切换为"仅阻塞 PR 新增错误"。BASE 已有的诊断不再阻塞 CI。这是有意设计（ratchet 策略），但团队需知晓语义变更。
2. **pyconfig / 依赖变更检测**：ratchet 工具仅过滤 `.py` 文件变更；若 PR 修改 `pyrightconfig.json`、`pyproject.toml`、`constraints/` 等导致未变更 `.py` 文件出现新诊断，ratchet 仍会检测到（因为全仓 pyright 比较），但 `has_any_py_changes` 为 False 时变更摘要显示"仓库无 .py 文件差异"，可能造成误导。不影响正确性。
3. **os.chdir 全局状态**：`_run_base_pyright_and_build_counter` 使用 `os.chdir` 切换到 BASE worktree 运行 pyright。虽然有 `finally` 恢复，但在多线程环境中不安全。当前 CI 为单线程执行，无实际风险。
