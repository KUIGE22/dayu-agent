## Findings

### 1-未修复-[中]-gateway 的字段 owner 校验仍可被伪装或 subtype 穿透，既能伪造 generic `CANCELLED`，也能让 completion 到持久化层才失败

- **入口/函数**: 动态 handler 返回值进入 `JobService.execute_claim` 后的 `JobFailure` / `JobCompletion` 快照、重建与收窄。
- **文件(行号)**: `dayu/investment/domain/jobs.py:329-344,417-434,1361-1392`；`dayu/services/job_service.py:780-830`；下游证据为 `dayu/investment/domain/jobs.py:675-735,840-891`、`dayu/host/worker.py:1144-1193`、`dayu/investment/storage/postgres_jobs.py:1493-1518,1547-1695,3306-3369`；缺口测试位于 `tests/application/test_job_service.py:661-677,2318-2492`。
- **输入场景**:
  1. handler 返回 exact `JobFailure`，但 `safe_error_code` 是外部对象；该对象的 `__class__` 属性返回 `SafeJobErrorCode`，并暴露 `value == "cancelled"`。这既可用公开 `JobFailure(...)` 构造器构造，也可用 constructor bypass 注入。
  2. handler 返回 exact `JobCompletion` / exact `CanonicalJobDocument`，但 `schema_name` 是 `str` subtype。其底层文本是合法 schema 名，canonical bytes/hash也完全合法。
- **实际分支**:
  1. Python 的 `isinstance(spoof, SafeJobErrorCode)` 会接受上述 `__class__` 伪装。`JobFailure.__post_init__` 与 gateway 都使用 `isinstance`，所以重建后的 failure仍保留外部对象；`is SafeJobErrorCode.CANCELLED` identity门禁不命中并返回该 failure。
  2. gateway虽严格 reparse bytes/hash且返回新的 base completion/document，但 `parse_canonical_document(..., schema_name=document_fields[0])` 原样复用 `schema_name` 对象；tuple equality也不把合法文本的 `str` subtype规范化为 plain `str`，因此新 DTO仍携带 handler持有的 foreign scalar identity。
- **预期行为**: handler非法/外部 owner返回必须在 Service dynamic trust gate统一收窄为 non-retryable `HANDLER_REJECTED`；generic `CANCELLED`只能来自 `PostgresJobStore` persisted cancel-intent分支。返回的新 base DTO应只含稳定的 domain-owned/plain immutable字段，不能把 handler可持有或伪装的字段 owner传给 Worker/Store。
- **实际行为**:
  1. spoof failure越过 `CANCELLED`门禁。generic failure receipt的矩阵比较也未识别该对象为 enum singleton，随后读取其 `.value`，可生成 `outcome="failed" / reason="failure" / safe_error_code="cancelled"` 的 canonical receipt；PG fail链还会把同一值写入 receipt/job/attempt safe-code列，制造计划明确禁止的 generic `CANCELLED`事实。
  2. foreign-schema completion被 gateway当作成功返回；Worker进入 `complete` 后，generic receipt builder的递归 JSON validator要求 `type(value) is str`，因此拒绝该 subtype并令事务回滚/Worker runtime failure，而不是在 gateway稳定返回 `HANDLER_REJECTED`。
- **直接证据**:
  - `jobs.py:1376` 和 `job_service.py:788` 均为 `isinstance(..., SafeJobErrorCode)`；`job_service.py:792-798` 重建后仍以 enum singleton identity检查 `CANCELLED`。
  - 独立对抗复现中，`isinstance(spoof, SafeJobErrorCode)` 为 `True`；公开构造与 constructor-bypass两类 exact `JobFailure` 均由 gateway接受，返回的新 failure仍以 identity持有 spoof且 `.value == "cancelled"`。
  - 将同一 spoof交给 `build_generic_attempt_receipt(... outcome=FAILED, reason=FAILURE ...)`，实际得到包含 `"safe_error_code":"cancelled"` 的 canonical receipt；`jobs.py:885-891` 的禁止集合未拦截，`732`读取 foreign `.value`。
  - `jobs.py:343` 接受 `str` subtype；`job_service.py:810-822` 把原 schema owner传给 strict parser后封装。独立复现确认 gateway返回新的 exact base completion/document，但 `actual.result.schema_name is foreign_schema_name`；紧接着 completion receipt构造抛 `JobInputError("receipt 必须是严格 canonical JSON")`，对应 Worker→Store真实链的 rollback/runtime-failure位置。
  - 现有 foreign-code test只覆盖 raw string、`None`与另一个 `Enum` owner（`tests/application/test_job_service.py:661-677`）；constructor/subtype test只覆盖 raw code、外层 DTO subtype与普通字段 mutation（`2318-2492`），没有 `__class__` spoof或 nested scalar subtype。
- **影响**: 一个错误或对抗性的 in-process handler仍可突破 cancellation唯一真源，写出 `failed/failure/cancelled` 自相矛盾的审计事实；也可返回 gateway声称已闭合的 completion，却在 PG收口时回滚并触发 lease recovery/runtime churn。两者都破坏“非法 handler返回统一 HANDLER_REJECTED”以及 receipt/state一致性。
- **建议改法和验证点**:
  1. `JobFailure.__post_init__` 与 gateway对错误码使用 exact owner检查（例如 `type(code) is SafeJobErrorCode`），重建后保证字段必为真实 enum singleton；不要把可伪装的 `isinstance`当信任证明。
  2. completion gateway在调用 foreign字段的方法前检查 document四字段的 exact scalar owner，至少要求 `type(schema_name) is str`、`type(schema_version) is int`、`type(canonical_bytes) is bytes`、`type(sha256) is str`；strict reparse后只返回 plain-field的新 base DTO。
  3. 新增 `__class__` spoof（公开构造与 constructor bypass）、spoof `.value` 在 gateway返回后变化、schema/bytes/hash scalar subtype测试；断言全部为 `HANDLER_REJECTED`且不进入 complete/fail。保留正常 failure/completion等值但非同 identity、strict parser、cancellation与 `asyncio.CancelledError` tests。
- **修复风险（低/中/高）**: 低；修复集中在动态边界与 enum构造不变量。若收紧全局 `CanonicalJobDocument` scalar owner，需先确认数据库 row decoder均产出 plain builtins；也可先仅在 gateway exact检查以避免无关 ripple。
- **严重程度（低/中/高/严重）**: 中。
