## 2. Accepted findings and fixes

### H-001 — fixed

- SEC market filing token owner 和 CN/HK 的 stage-C、PDF-SHA skip 两个 token owner 均在
  commit PONR 前捕获 `GeneratorExit`、`asyncio.CancelledError`、domain cancellation 及其它
  `BaseException`，回滚原 token 恰好一次并 bare re-raise 主异常。
- `finalization_started` 在调用 `commit_batch` 或正常 `rollback_batch` 之前设置；commit 调用开始后
  即使出现 response-loss error 也不再错误补偿 rollback，由既有 journal/recovery owner 收敛。
- rollback failure 通过 `BaseException.add_note` 附加到主异常，best-effort 日志自身也不能遮蔽主异常。
- 真实 `FsBatchingRepository` 测试覆盖 SEC/CN outer `aclose` 与 task cancellation：begin 1、
  rollback 1、commit 0、直接 inner close 1、active batch/staging/publish 清空，且同 ticker 随后
  可再次 begin。SEC task-cancel case 在 token owner 正等待 direct inner `__anext__`
  时注入真实 `asyncio.CancelledError`，不是 caller 自行转换成 outer `aclose`。另锁定
  rollback-secondary 与 commit-response-loss 两个 PONR 反例。

### M-001 — fixed

- SEC ordinary terminal 必须含 `report_date` key（值允许显式 `null`）和 canonical
  `internal_document_id`，分别精确等于 started `report_date` 与 `accession_number`；可选
  terminal `accession_number` 若出现也必须一致。
- CN/HK ordinary terminal 必须含并精确匹配 `fiscal_year`、`fiscal_period`、`source_id`。
  `_build_filing_result`、fast-skip builder 与 outer candidate-failure builder 已补齐真实 identity，
  nested、flat 与 final `result.filings` 从同一对象传播。
- `candidate_not_found` 保持唯一、先于 ordinary required-shape 校验的无-started例外。
- 参数化测试逐字段覆盖 missing/mismatch；真实 SEC/CN producer 的 normal、skip 与
  failure/error terminal 再经 public source-sync runtime 消费，CN `source_id` 端到端闭合；
  `candidate_not_found` 也以真实 CN producer -> runtime 路径证明例外分支。

### M-002 — fixed across both corrective passes

- source-sync root 显式保存 stream/body primary `BaseException`，直接 inner `aclose()` 恰好调用一次；
  第一 pass 已确保 ordinary cleanup failure 只有在无更高或同级 body primary 时才成为 winner；
  第二 pass 再闭合 cleanup-wait cancellation、intrinsic close cancellation/process-exit 与 repeated cancel，
  完整仲裁规则见 RR-M-001。
- 最终优先级固定为 process-exit、`asyncio.CancelledError`、domain cancel -> `CANCELLED`、已证明
  invariant -> `INVARIANT_FAILED`、ordinary stream/close exception -> `UNAVAILABLE`；已有 body
  asyncio cancel 必须保持原对象，所有 lower-priority secondary 只附加 note。
- 组合矩阵覆盖 asyncio/domain/invariant/generic primary + close failure，以及 clean + generic/asyncio
  close；所有 case 均断言 `aclose_calls == 1`。

### L-001 — fixed

- 仅 `dayu/fins/domain/source_sync.py` 与 `dayu/fins/source_sync_runtime.py` 补齐中文 module/class
  overview，以及所有 function/method 的中文 `Args:`、`Returns:` 或 `Yields:`、`Raises:`。
- `tests/investment/test_architecture_boundaries.py` 新增 exact-two-owner fail-closed AST gate，并以
  missing docstring、英文 module、英文 function、缺 section 四类反例证明 guard 不会 fail open。
- 未进行 legacy 全仓 docstring 清理。

### RR-M-001 — fixed in second corrective pass

- source-sync root 为 direct inner 建立唯一具名 owned close task；child coroutine 在自身边界捕获任意
  `BaseException` 并作为值返回，避免 intrinsic `asyncio.CancelledError`、`KeyboardInterrupt` 或
  `SystemExit` 直接冲出 event loop。owner 以 `asyncio.shield` 循环抵抗任意次外层 task cancel，记录
  cleanup wait 第一份取消，直到 close task terminal 并同步读取结果；不调用 `uncancel()`、不二次
  `aclose()`、不留下 detached orphan。
- 最终统一仲裁为 body/close `KeyboardInterrupt` 或 `SystemExit` > body/close/cleanup-wait
  `asyncio.CancelledError` > domain cancel > proven invariant > ordinary exception；同级保持
  body -> cleanup-wait -> close，故 body 首份 asyncio cancel 对象保持不变。所有 secondary 只以 note
  附加，note 失败也不能遮蔽 winner。
- Controller 接受的同型 SEC token/direct-inner owner 闭合也在本轮完成：batching 与 non-batching 两支
  使用本模块私有 owned close task/shield/reap；timeout cancellation 仍由 `asyncio.timeout` 正确转换，
  commit/rollback PONR flag 未移动，pre-PONR winner 仍触发同 token exact-once rollback。
- 真实 `task.cancel()` + gate 测试覆盖 generic/domain/invariant + cleanup cancel、body 首 cancel +
  第二/第三 cancel、clean + intrinsic close cancel、close process-exit、SEC timeout + blocking close。
  每路证明 `aclose_calls == 1`、close completed、task done/result reaped、无同名 pending orphan；SEC
  batching 同时证明真实 FS active/staging/publish 清空且同 ticker 可 re-enter。

### RR-M-002 — fixed in second corrective pass

- 接受 CN/HK `candidate_not_found` 前，若 `state.started.values()` 已有同 form ordinary filing 即
  invariant；写入 ordinary `FILING_STARTED` 前，若该 form 已在 `candidate_forms` 也立即 invariant。
  `started` 在 ordinary terminal 后仍保留，因此同一 guard 同时覆盖 started->candidate 与
  terminal->candidate，不按 active document 或 synthetic document id 错误收窄。
- CN/HK 两市场参数化锁定 candidate->started/terminal、started->candidate、terminal->candidate
  三种同-form 顺序全部 `INVARIANT_FAILED`；合法反例证明不同 form synthetic+ordinary 的两种顺序、
  不同 document/source-id 的同-form多 ordinary、不同 form 多 candidate 仍合法，duplicate candidate
  的既有每-form唯一规则不回退。每个矛盾序列都携带精确 terminal-order pipeline mirror，final result
  不能洗掉先前矛盾。

### RR-L-001 — fixed in second corrective pass

- 在最终 source/test bytes 上按 accepted plan section 11.1 的五个 exact owner tuple 全部重新执行 fresh
