## 3. Findings

### 1-未修复-[低]-根因叙述把 dylib 位置写成「同目录」
- **位置**：`S22-CTRL-012` 首段（plan 第 189 行）与 codex plan-fix 第 14 行
- **问题类型**：其它（证据性叙述不精确）
- **当前写法**：「POSIX 默认 `symlinks=False` 会复制带 rpath 的 Python launcher，却不复制**同目录** `libpython3.11.dylib`」
- **反例/失败场景**：实际布局中 dylib 不在 launcher 同目录：`bin/python3.11` 链接 `@rpath/libpython3.11.dylib`，唯一 `LC_RPATH=@executable_path/../lib`，dylib 位于 `lib/libpython3.11.dylib`（`bin/` 的兄弟目录）。「同目录」叙述若被后续维护者当作普适规律推广（例如 Linux `$ORIGIN/../lib`、其它 relocatable runtime），会误导平台特判方向；而本勘误恰好禁止平台特判。
- **为什么有问题**：勘误的根因段是「为什么只改 venv 策略、不改 loader/archive」的依据。机制结论正确（copy 不带 dylib 依赖、symlink 经真实路径解析），但位置描述与机器事实不一致，削弱证据严谨性；修复本身不受影响。
- **直接证据**：`otool -L / -l ~/.local/share/uv/python/cpython-3.11.15-macos-aarch64-none/bin/python3.11`；`ls lib/` 含 `libpython3.11.dylib`；本机复现 copy→`SIGABRT: 6`、symlink→成功
- **影响**：仅叙述精度；不产生错误代码或状态风险
- **建议改法和验证点**：把「同目录」改为「`bin/` 兄弟目录 `lib/`（rpath `@executable_path/../lib`）」或直接引用 rpath 描述；无需改实现与测试
- **修复风险（低/中/高）**：低
- **严重程度（低/中/高/严重）**：低

### 2-未修复-[低]-真实门禁的 sanitized 环境未清 `PIP_TARGET/PIP_USER/PYTHONUSERBASE/VIRTUAL_ENV/CONDA_PREFIX/PIP_FIND_LINKS`
- **位置**：`S22-CTRL-012` 第 4 条（plan 第 196 行）
- **问题类型**：测试缺口 / 门禁硬化
- **当前写法**：清空 DYLD 四变量、`PYTHONHOME`、`PYTHONPATH`、index/extra-index 及大小写 proxy，设 `PIP_NO_INDEX=1`、fresh empty pip cache
- **反例/失败场景**：
  1. operator shell 若带 `PIP_TARGET`/`PIP_USER=1`：安装脚本子进程继承该变量（`_run_install_script` 是 `dict(os.environ)` + `PYTHON_BIN`），归档被装到 venv 之外，随后 venv python `import dayu` 失败 → 真实门禁假性 FAIL → 触发计划自身 STOP → Controller 往返，与勘误目的无关的返工；
  2. `PIP_FIND_LINKS` 指向另一份离线目录时，`PIP_NO_INDEX=1` 仍允许 find-links 生效，缺 wheel 可能由该外部目录满足，削弱「归档自足、无 fallback」证明的纯度（归档自足本身由 172 wheel / resolver 另证，故为削弱而非破坏）。
- **为什么有问题**：门禁语义是「证明成功不依赖 loader 注入、无网络/外部 fallback」；sanitize 集合是门禁合同的一部分，未覆盖的继承变量会让同一门禁在不同 operator shell 下结果漂移。
- **直接证据**：`utils/smoke_test_offline_bundle.py:124-135`（install child 继承 `os.environ`）、`S22-CTRL-012` 第 4 条清单
- **影响**：真实门禁可复现性/确定性下降；假性 FAIL 造成 STOP 往返；无假性 PASS 路径（venv 默认 `ENABLE_USER_SITE=0` 且 `PYTHONPATH` 已清，user-site 不会混入）
- **建议改法和验证点**：把上述变量加入清空清单（或改用受控最小 env 构造父进程后再附加 `PYTHON_BIN`）；验证点不变
- **修复风险（低/中/高）**：低
- **严重程度（低/中/高/严重）**：低
