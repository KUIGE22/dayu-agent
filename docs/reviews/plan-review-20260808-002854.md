## 2. 推荐方案：精确私有 TypedDict

### 2.1 TypedDict 定义

在 `research_workbook.py` 模块顶部（`from __future__ import annotations` 之后）新增：

```python
from typing import TypedDict


class _ResearchWorkbookEvidence(TypedDict):
    """研究手册证据记录 — 对应 item.evidence[] 元素。"""
    source: str
    reference: str
    finding: str


class _ResearchWorkbookItem(TypedDict):
    """研究手册单项 — 对应 section.items[] 元素。"""
    item_id: str
    prompt: str
    status: str
    response: str
    evidence: list[_ResearchWorkbookEvidence]
    analyst_notes: str
    evidence_required: bool


class _ResearchWorkbookSection(TypedDict):
    """研究手册章节 — 对应 payload.sections[] 元素。"""
    section_id: str
    title: str
    category: str
    items: list[_ResearchWorkbookItem]
```

### 2.2 提取后的函数签名

```python
def _append_research_workbook_section(
    sections: list[_ResearchWorkbookSection],
    *,
    normalized: str,
    current_title: str,
    current_category: str,
    current_items: list[str],
) -> None:
    """将当前累积的 items 追加为一个新 section 到 sections 列表。

    Args:
        sections: 可变 sections 列表，原地追加。
        normalized: 归一化后的模板名，用于稳定 ID 哈希。

        None — 副作用为 sections.append(...)。

        无显式异常。空 category 或空 items 时静默跳过。
    """
```

## 4. Adversarial Failure Pass

### 4.1 `from __future__ import annotations` 影响

`research_workbook.py` line 3 有 `from __future__ import annotations`。这意味着：

- **运行时**：所有注解变为字符串延迟求值（PEP 563），TypedDict 的 `__annotations__` 在运行时是字符串而非类型对象。
- **pyright**：不受影响，pyright 在编译期解析注解。
- **TypedDict 兼容性**：Python 3.11 + `from __future__ import annotations` + `TypedDict` 完全兼容。项目已有先例：`dayu/contracts/agent_types.py` 同样使用 `from typing import TypedDict`（虽无 `__future__` 注解，但 `dayu/contracts/model_config.py` 使用 `from typing import Literal, TypeAlias, TypedDict` 且 pyright 通过）。
- **结论**：`from __future__ import annotations` 不影响 TypedDict 的正确性。

### 4.2 Dict 兼容性

| 操作 | 代码位置 | TypedDict 兼容性 |
|------|----------|-----------------|
| `isinstance(section, dict)` | line 190, 338, 625 | ✓ — TypedDict 是 dict 子类 |
| `section["category"]` | line 114, 202, 341 | ✓ — TypedDict 支持 `__getitem__` |
| `item["status"] = "answered"` | line 642 | ✓ — TypedDict dict 是可变的 |
| `evidence.extend(...)` | line 654 | ✓ — list 字段可变 |
| `sections.append(section_dict)` | line 77（提取后为函数内构造） | ✓ — `list[TypedDict].append(dict)` 兼容 |
| `deepcopy(workbook_payload)` | line 619 | ✓ — TypedDict 运行时即普通 dict |

### 4.3 Mutation 安全性

提取后的 `_append_research_workbook_section` 对 `sections` 做 `.append()`。Python 引用语义保证：传入的 `sections` 列表与调用方的 `sections` 是同一对象。`len(sections)` 在 line 57 用于生成位置索引 — 提取后此逻辑不变，因为 `sections` 参数就是同一可变列表的引用。

**关键语义**：`section_index = len(sections)` 在每次 append 前取值，确保重复 heading 获得不同 hash。提取后此语义由函数参数 `sections` 维持，不依赖闭包捕获。

### 4.4 过约束风险

TypedDict 默认 `total=True`（所有字段必需）。如果从磁盘加载的旧版 JSON 缺少 `evidence_required` 字段（未来 schema 演进），TypedDict 的类型检查不会在运行时报错（TypedDict 是纯类型检查构造），但 pyright 会在构建字面量时要求所有字段存在。

**评估**：当前 `_append_research_workbook_section` 只**构造** sections（不从 JSON 读取），所有字段始终显式赋值。从 JSON 读取的路径（`_load_json_object` → `validate_research_workbook_payload`）使用 `dict[str, object]`，不受 TypedDict 约束。因此 `total=True` 不会造成过约束。

### 4.5 调用点语义验证

| 调用点 | 行号 | 触发条件 | 提取后行为 |
|--------|------|----------|------------|
| heading 切换 flush | 89 | `stripped.startswith("## ")` | 先 flush 上一 section，再更新 `current_title`/`current_category`/`current_items` |
| 文件结束 flush | 107 | 循环结束 | flush 最后一个 section |

两个调用点参数完全相同。提取后签名从无参闭包变为 5 个显式参数，调用点需传入 `sections, normalized, current_title, current_category, current_items` — 全部来自 `build_research_workbook_payload` 的局部变量。

## 7. Open Questions

1. **`sections` 变量注解同步**：`build_research_workbook_payload` line 45 的 `sections: list[dict[str, object]]` 需同步改为 `list[_ResearchWorkbookSection]`。变更范围仅限同一函数内部，不扩 scope。返回值类型 `dict[str, object]` 不受影响 — `list[_ResearchWorkbookSection]` 可赋值给 `object`。

2. **是否需要 v4.5 plan erratum**：**是**。Plan line 699 的签名与 CLAUDE.md 硬约束冲突。建议 erratum 内容：`W16 签名从 list[dict[str, object]] 纠正为 list[_ResearchWorkbookSection]（TypedDict），以符合 CLAUDE.md 禁止 object 的硬约束`。

3. **存量 `dict[str, object]` 是否应全面替换**：本模块 17 个公开函数使用 `dict[str, object]`。本次 Slice 4 仅覆盖 `_append_research_workbook_section` 的提取，不触及存量签名。全面 TypedDict 化是独立的改进项，不在本次 review 范围内。

4. **`_ResearchWorkbookEvidence` 是否必要**：严格来说，Slice 4 的 `_append_research_workbook_section` 只构造空 `evidence: []`，不需要 `_ResearchWorkbookEvidence` TypedDict。但 `_ResearchWorkbookItem.evidence` 字段需要一个精确的元素类型 — `list[dict[str, str]]` 比 `list[dict[str, object]]` 更精确且符合硬约束。定义 `_ResearchWorkbookEvidence` 是最小成本的正确选择。

5. **`evidence_records` 参数类型**（line 699: `list[dict[str, object]]`）：这是 `write_research_workbook_update` 的参数，不在 Slice 4 范围内。但它是同一模块中另一个含 `object` 的模块级签名。如果后续全面 TypedDict 化，应改为 `list[_ResearchWorkbookEvidence]`。
