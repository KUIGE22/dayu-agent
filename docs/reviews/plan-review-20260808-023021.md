### 1.2 声明二：普通 import 新增 F401×2，显式同名 alias 消 F401 但新增 PLC0414×2

**当前 write.py 使用显式同名 alias**:
```python

_validate_live_smoke_plan_args as _validate_live_smoke_plan_args,
```

| 策略 | F401 | PLC0414 | 效果 |
|---|---|---|---|
| 普通 import（无 alias）| **触发 ×2**（unused import） | 0 | 两个符号无生产 caller → ruff F401 |

**结论**: 声明二 **证实**。当前代码处于"消 F401 但新增 PLC0414"的中间态。无论选择哪种保留策略，都无法同时满足 F401=0 和 PLC0414=0，除非删除 import。✓

### 1.3 声明三：保留仅服务旧测试/direct import 的 binding 违反禁止 compat re-export 与零 lint

**AGENTS.md 编码硬约束**:
> 禁止兼容性代码：
> - 兼容性 re-export：仅为保持旧导入路径而转发符号。

**两个符号的 re-export 动机分析**:

| 符号 | write.py 生产用途 | 测试用途 | 动机 |
|---|---|---|---|
| `_validate_challenger_run_plan_args` | 无 | `test_write_cli_dispatch.py:609-610` identity 断言 | **纯 compat re-export** |
| `_validate_live_smoke_plan_args` | 无 | `test_write_cli_dispatch.py:613-614` identity 断言 + `test_cli_running_config.py:26,2436,2444` direct import/call | **纯 compat re-export** |

这两个 import 的存在理由是"保持旧导入路径"——测试代码从 `write.py` import 这些符号，所以 `write.py` 需要转发。这正是 AGENTS.md 明确禁止的"兼容性 re-export"。

同时，当前 lint 状态不为零（PLC0414×2），违反 pyright/ruff 零违规门禁。

**结论**: 声明三 **证实**。保留这些 binding 违反两条约束。✓
