## 直接证据与裁决

`JobService.claim(scope, worker_id)` 与 `JobService.reserve_agent_run_correlation(scope, lease)` 是独立 public signatures，且当前架构没有向 caller 暴露共享 PG transaction context；因此前者 commit 后、后者开始前的 crash window 必然存在。把它称为“同一 PG transaction”会错误掩盖无 Host side effect 的 incomplete operation。

`ExecutionContract` 的实际 owner 是 `dayu.contracts.agent_execution`，当前 dataclass 必填字段为 `service_name`、`scene_name`、`host_policy`、`preparation_spec`、`message_inputs`、`accepted_execution_spec`；`execution_options` 与 `metadata` 有默认值。现有 `tests/application/test_host_executor.py` 的 `_minimal_accepted_execution_spec()` 和直接构造方式证明 fake future caller 可建最小合法 fixture，无需改 production glue 或 contract。

## Active Host correction

后续 steer 发现一个真实风险：把 Host missing 与 `CREATED/QUEUED/RUNNING` 合成“可 generic recover”会令旧 Host/model 仍活跃时产生新 attempt。计划现定义互斥结果：

1. `reserved` + Host missing → `NO_HOST_RUN`；仅这一分支可 generic recover。
2. Host `CREATED/QUEUED/RUNNING` → `HOST_ACTIVE_WAIT`；保持 current attempt/correlation，不 recover、不 retry、不 second entry。
3. Host terminal → terminalize 或 stale 路径；已观察 Host 后 row 消失 → `INVARIANT_FAILURE`。

`HOST_ACTIVE_WAIT` 的明确未来 owner 是 Slice 2.2 worker：以其正数 `host_active_reobserve_interval_seconds` 重观测，PG `deadline_at` 是 active-wait 上界；到期后由该 worker/Host lifecycle 发起幂等 `cancel_run` 并只继续观察，绝不 generic recover 或 claim 新 attempt。Slice 2.1 不注册或实现该 worker，也不投射 Host cancel。相应计划测试证明 active Host 不会 recover、新建 attempt 或二次模型进入，而 reserved+missing 会安全 recover。
