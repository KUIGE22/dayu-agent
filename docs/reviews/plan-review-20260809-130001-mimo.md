## 新增 open findings

### L-1-未修复-[低]-空 `form_type` 会让 `normalize_form` 抛 ValueError，退化为不可诊断 exit 2

- **位置**：plan §5.1:133、§5.2:149、§5.1:136
- **问题类型**：契约缺失（边界未定义）
- **当前写法**：plan:133 要求 discovery row 记录“经 `normalize_form` 得到的 canonical forms”；plan:136 规定 form 比较唯一复用 production `normalize_form`。计划未定义 owner `form=` 为空时的行为。
- **反例/失败场景**：download 明细行渲染为 `form=`（空值）。`normalize_form("")` 抛 `ValueError`。按 plan:261，unexpected `Exception` 只输出静态脱敏摘要并 exit 2 —— operator 拿到的是一个无类别、无行号的通用失败，而不是本计划刻意设计的 categorized fail-closed 停机。这恰好绕开了 M-3 刚建立的诊断通道。
- **直接证据**：`dayu/fins/cli_formatters.py:422` `f"form={item.form_type or ''}"`（可渲染空值）；`dayu/fins/pipelines/sec_form_utils.py:53-55`：
  ```python
  normalized = form_type.strip().upper().replace(" ", "")
  if not normalized:
      raise ValueError("form_type 不能为空")
  ```
- **影响**：低概率但真实；命中时诊断信息弱于计划自身承诺的 fail-closed 语义。
- **建议改法和验证点**：plan §5.1:136 补一句：download row 的 `form=` 为空时，该 row **不调用 `normalize_form`**，直接归类为 `structure_reject` 类别的 fail closed（进 `stdout_summary` 的类别 + 行号），不得让 `ValueError` 逃逸为 unexpected exception。测试补一条空 `form_type` 的 download stdout，断言 stop 类别与行号可见、非 exit-2 通用路径。
- **修复风险**：低。
- **严重程度**：**低**

### L-2-未修复-[低]-`上传材料结果` 的可信结构未逐项枚举必需/可选，与“顺序精确、必须唯一”规则存在张力

- **位置**：plan §5.1:135、§5.2:150
- **问题类型**：契约缺失
- **当前写法**：plan:135 只对 download 与 process 逐节写死 grammar（download `ticker → status → 汇总 → optional warnings → 三节`；process 两个 summary + 六节），upload_material 只在 plan:150 按 action 说了字段可空性，**没有说明哪些 scalar 行必然存在、哪些条件缺席**。而 plan:135 的总则是“anchor 后固定 scalar/summary/section header 必须唯一、顺序精确”。
- **反例/失败场景**：`skip` action 下 `source_fingerprint`/`report_date` 缺席（计划已允许），但实施 Agent 若按 plan:135 总则要求“固定 scalar 必须出现”，会把合法 skip 判为 structure missing → fail closed。
- **为什么有问题**：owner 用 `_append_optional_field_lines` 逐字段跳过空值，因此 upload_material 的可选行**天然是稀疏的**，只有 `pipeline / ticker / status / material_action` 四行恒存在，`files:` section header 恒存在。计划把这条事实留给了实施 Agent 推断。
- **直接证据**：`dayu/fins/cli_formatters.py:769-798`——`lines` 硬编码只含 title/`pipeline`/`ticker`/`status`/`material_action`，其后 15 个字段全部走 `_append_optional_field_lines`；`:1042-1045` 明确 `if value is None or value == "": continue`；`:797` `lines.append("files:")` 恒存在。
- **影响**：合法 `skip` 路径可能被误判停机；或实施 Agent 自行放宽 upload grammar，破坏三类 stdout 规则一致性。
- **建议改法和验证点**：plan §5.2:150 补一句显式枚举：upload_material 的必存可信结构精确为 `上传材料结果 → - pipeline → - ticker → - status → - material_action → …条件可选行（按 owner 固定顺序，允许缺席但不允许乱序/重复）→ files:`；`files:` 之后为 opaque tail。测试覆盖 create（全字段在场）与 skip（fingerprint/report_date 缺席）两态解析均成功。
- **修复风险**：低。
- **严重程度**：**低**
