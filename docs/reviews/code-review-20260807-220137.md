## 10. Adversarial Failure Pass

### F-01: `receipt_source_path` isinstance guard（Low）

**位置**: `write_model_configuration_rollback.py` `build_...` 和 `verify_...` 函数
**问题**: `isinstance(receipt_source_path, str)` guard 使用 `TypeError` 而非 `ValueError`，与模块内其他校验（`require_text` → `ValueError`）不一致。
**影响**: 低。运行时行为正确，仅异常类型不统一。
**建议**: 后续 slice 统一为 `ValueError` 或改用 `require_text`。

### F-02: `changed_roles` isinstance guard（Low）

**位置**: `write_model_challenger_promotion.py:1024`, `write_model_configuration_change.py:1487`
**问题**: `isinstance(changed_roles, (dict, list, str))` guard 的 `raise TypeError("... must be a list")` 错误信息与实际接受类型（dict, str）矛盾。
**影响**: 低。运行时防止了 bool/int/None 崩溃，错误消息仅在极端畸形 JSON 下触发。
**建议**: 后续 slice 收紧为 `isinstance(changed_roles, list)` 或调整错误消息。

### F-03: `canonical_json_str(dict(...))` adapter 对称性（Pass）

**位置**: 10 处 call-site adapter
**检查**: 所有 `canonical_json_str(dict(mapping_value))` 调用中，`dict()` 复制了 identity-return 的 Mapping 顶层，与旧 `_canonical_json(json.dumps(dict(value)))` 行为完全一致。比较两侧要么都用 `dict()`，要么一侧已是 dict。
**结论**: 无问题。

### F-04: `require_mapping` 输入扩宽是否引入意外接受（Pass）

**检查**: 旧签名 `value: ModelConfigJsonValue` 仅含 `dict` 递归分支（`str | int | float | bool | None | list[...] | dict[str, ...]`），不含抽象 `JsonObject = Mapping[str, ModelConfigJsonValue]`。因此旧签名在静态类型层面不接受非 `dict` 的 `Mapping`（如 `MappingProxyType`），但运行时函数体 `isinstance(value, Mapping)` + identity-return 对任意 `Mapping` 均正确工作。v4.4 将输入类型显式扩宽为 `ModelConfigJsonValue | JsonObject`，是静态类型修正，使 pyright 能正确推断 `Mapping[str, Any]` payload（rollback 5 个 public validator）经 `JsonObject` 协变分支通过。运行时行为零变化——原实现本就 `isinstance(Mapping)` + identity-return。
**结论**: 无问题。纯静态类型修正，运行时零语义变更。
