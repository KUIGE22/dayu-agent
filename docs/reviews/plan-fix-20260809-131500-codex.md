## Final contracts

### Material import state machine

- `material_action` 只表示 requested/resolved create/update intent，本计划不传 delete；delete 或未知 action 为结构拒绝。
- `owner_status=ok` 时 stable document ID、source fingerprint、report date、repository meta/primary SHA 全部必需。
- `owner_status=skipped` 时 source fingerprint/report date 可 null，但 stable document ID 必须等于 plan，repository meta/primary SHA 必须等于 `plan.price_material_sha256`。
- Download/process 仍只允许 owner_status=ok；它们的 exit-0 cancelled 必停。不得用全局 status gate混淆三类命令。

### Process evidence

- 六个 section header 唯一有序，source_kind/status 完全由所在 section 派生。
- 行内唯一可信字段是 document ID；`status=` 及其后的 reason/form/quality/其它 optional parts 都不进入 evidence。
- quality 只从 `ProcessedDocumentRepositoryProtocol` 读取并作为既有 processed state fingerprint 与 source inventory 闭合。

### Formatter rejection boundary

- Download `form=` 为空先分类为 `structure_reject`，stdout summary 记录类别与 line；不调用 normalizer，也不让 ValueError 逃逸为 unexpected exit 2。
- Upload 必需顺序是 title→pipeline→ticker→status→material_action；随后 15 个 owner 固定顺序 optional fields 可缺席但不得重排/重复；`files:` 必需唯一，之后行 opaque。
