  漏掉真正要禁止的 reset-triggered AUTO。

## 2. 唯一计数与观察边界

测试契约现区分两个合法 owner：

1. **Company upsert owner**：workflow 前的 company upsert 短
   `AUTO_ATOMIC_ALLOWED` batch 保持允许；它不计入本次 overwrite-reset 负向断言，
   继续由 company storage owner 的既有 admission 测试证明；
2. **Upload service owner**：`DoclingUploadService.execute_upload` 的同-core
   per-document explicit batch 必须恰好一次 begin；每次
   `reset_source_document` 发生时 source-owner observer 必须看到同-core token active；
   随后成功恰好一次 commit，reset 后/commit 前失败恰好一次 rollback；
3. **禁止项**：零个由 `reset_source_document`/overwrite reset 在 service explicit
   batch 之外触发的 AUTO batch，零 nested/second service batch。若 workflow 重新插入
   pre-reset，source-owner observer 会在无 service token 时立即失败；
4. filing 与 material 两条真实 workflow 分别执行相同矩阵，保留 action/status/document
   id/event-order 与旧 source/blob bytes assertions。

这一定义不依赖全局 batch 总数猜测，也不需要生产 seam、wrapper、reflection 或额外
test owner。
