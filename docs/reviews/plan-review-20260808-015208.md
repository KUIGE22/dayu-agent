## 2. S5-CTRL-02 逐项验证: `setup_model_name` monkeypatch 迁移

### 2.1 Python 函数 globals 绑定证明

Python 语言规范: 函数对象在定义时捕获其所在模块的 `__globals__` 字典。函数体内对自由变量（如 `setup_model_name`）的解析始终查找此 `__globals__`，而非调用栈上任何模块的命名空间。

```python
# _write_config_helpers.py（Slice 5 后）
from dayu.cli.dependency_setup import setup_model_name  # binding: _write_config_helpers.setup_model_name

def _resolve_write_model_override_name(args):
    return setup_model_name(args).model_name  # 解析 _write_config_helpers.setup_model_name
```

若测试执行 `monkeypatch.setattr("dayu.cli.commands.write.setup_model_name", mock)`:
- 这只重绑了 `write` 模块的 `setup_model_name` 属性
- `_write_config_helpers.setup_model_name` 不受影响（不同模块的 `__globals__`）
- `_resolve_write_model_override_name` 仍调用真实的 `setup_model_name` → 测试静默失败

**结论**: monkeypatch 目标**必须**从 `write.setup_model_name` 迁到 `_write_config_helpers.setup_model_name`。✓

### 2.2 Monkeypatch 计数验证

**输出**: `13`

与 plan §1.8:338-339 和 §5 Slice 5:845-847 声明的 "精确 13 处" 一致。✓

（MiMo 013316 声称 11 处——源码 grep 确认为 13。MiMo 计数偏少。）

### 2.3 Compat re-export 禁止验证

Plan §5 Slice 5:840-843 明确:
> "不得添加 compatibility re-export、wrapper、lazy import 或同步 seam"

MiMo (013316) 提议 `write.py` re-export `setup_model_name` 以保持旧 monkeypatch 路径有效。Controller REJECTED，理由:
1. Re-export 不能使旧 monkeypatch 生效（Python globals 绑定在定义模块——见 §2.1）

**验证**: Controller 裁决与 Python 语义和 AGENTS 约束一致。✓
