## 5. Fragile Module-Unimportability Test Rejection

**Prior review (042838 §5.3)** proposed:

> Unit test: Call `_run_write_model_configuration_application` with mock args; verify it produces a valid snapshot mapping without importing `_write_snapshot_builder`. (Indirect: the function must succeed without `_write_snapshot_builder` being importable — test by temporarily making it unimportable.)

**v4.9 plan explicitly rejects this approach** (Slice 6 verification section):

> 不得通过临时令 `_write_snapshot_builder` 不可 import 来证明依赖方向，该做法脆弱且把测试耦合到 import 机制。

**Assessment**: The rejection is correct. Making a module unimportable (e.g., via `sys.modules` manipulation or `ImportError` monkeypatching) is:
- **Fragile**: Breaks if import implementation changes (lazy imports, conditional imports, `__init__.py` re-exports)
- **Indirect**: Tests the absence of an import rather than the presence of the correct mechanism
- **Coupled**: Ties test correctness to CPython import internals

The v4.9 replacement (AST structural audit + real callback tests) is strictly superior:
- AST audit proves the import doesn't exist in the source code (structural, not behavioral)
- Real callback tests prove the partial works correctly (behavioral, not structural)
- Together they provide both static and dynamic guarantees without import-mechanism coupling

**Fragile test rejection: CONFIRMED SOUND.**
