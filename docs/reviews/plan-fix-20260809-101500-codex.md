## Blocking evidence

Slice 2 pre-edit 审计确认，accepted Slice 1 的 `AcceptancePlan` 严格 schema 只绑定目标、as-of、代码环境、package inputs、price digests、预算、wall-clock、grace 与固定 13 research artifacts。`to_json()` / `parse_acceptance_plan()` 不接受 run root、全部 allowlisted argv、模型绑定或 required environment presence。

同一 accepted plan 的 §§4.1、5.1、8.2 与 Slice 2 又要求这些事实进入唯一 `acceptance-plan.json` fingerprint，并要求 run root、argv、model 或 environment identity 漂移在 subprocess 前 fail closed。原 Slice 2 白名单不允许修改 contracts；在 CLI 模块另造 envelope 会产生第二 schema/fingerprint 真源。因此 implementation worker 按 stop condition 在 clean HEAD `a6cc350`、零编辑状态停止。

## Controller decision

- **ACCEPT A：扩展唯一 `AcceptancePlan`。** Slice 2 白名单加入 `utils/investment_agent_acceptance_contracts.py`；在原 frozen dataclass、strict parser、canonical JSON 和 fingerprint 上增加执行身份。
- **REJECT B：独立 execution-plan envelope / 双 fingerprint。** 它会让 evaluator、runner 与 verify 分别依赖不同身份，并破坏 `acceptance-plan.json` 单一运行身份。
- `utils/investment_agent_acceptance_evaluator.py` 不进入 Slice 2 白名单。它当前不导入或消费 `AcceptancePlan`，扩展 dataclass 不影响 evaluator；真实跨模块耦合是 evaluator 会把 `PhaseReceipt.to_json()` 作为 acceptance-owned output 扫描，因此 PhaseReceipt v2 必须在 contracts owner 内输出安全 token + digest。若实现期证明仍需 evaluator 变更，必须再次 STOP，而不是扩大 scope。

## Exact contract correction

Slice 2 必须增加不可变、严格收窄的 plan-owned types：

1. 规范化精确 `run_root` identity；
2. ordered phase specs：phase name + one-or-more argv token tuples；只允许计划列出的三组 download、price import、process、write preflight、paid write+materialize、validators 顺序；terminal verify 作为 plan-owned enum 在 fingerprint 计算后固定派生，避免自引用；
3. primary/audit 模型绑定，精确为 DeepSeek 与 MiMo 当前获准名称；
4. required environment names 与逐项 presence boolean；不存 value、hash 或原文；
5. 所有字段进入 `to_json()`、strict parser 与唯一 fingerprint；unknown/missing/duplicate/reorder/empty token/extra command 均 fail closed；
6. deterministic tests 注入 presence mapping，不读取宿主环境；只有 Slice 5 获授权 live prepare 才检查真实 presence；
7. raw local plan 可为执行消歧保留绝对 argv，但不得提交或复制进 phase/acceptance receipt、baseline、completion report；对外只保留 locator/digest/SHA-256。
